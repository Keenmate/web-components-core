PG01 · The window.components registry

registerComponent(tag, Class, { config, logging?, shouldAutoDefine? }) publishes one entry per tag — version(), config, logging (the bundle's controls, when a bundle was passed), register() and getInstances() — and defines the element (unless shouldAutoDefine: false; then register() does it, idempotently). An entry the page created before the script loaded is adopted: the same object gains the registry members and keeps its own keys. Instances are tracked by BlissElement itself, on connect / disconnect (a DOM move re-tracks the same element, no duplicate), so getInstances(tag) and getConnectedTags() (tags with at least one connected instance) need no per-component bookkeeping. The page-wide logging, renderLoadingCallback, motion and responsive* members are non-enumerable, so Object.keys(window.components) still lists tags only. The readout's getInstances() also lists PG03's two loader demos (#demo-pg-load-a / -b) and PG04's #demo-pg-c / -d: they are <core-demo-pg> elements too. Remove the last one removes only elements added here, so it does nothing until you add one. 


            

            
<script>  // before any module
  window.components = { 'core-demo-pg-early': { note: 'set by the page before core loaded' } };
</script>

PG02 · Logging: per tag, per instance, page-wide

            

                createLoggers(namespace, categories?) returns one colour-prefixed
                NAMESPACE:CATEGORY logger per category (default INIT / DATA /
                UI). The closest level wins: element → component type → page → warn. Nothing is
                set by default, so warnings and errors show and debug/info need enableLogging() (default level
                debug) at some layer; disableLogging() sets a layer to silent,
                resetLogging() clears it. Inside a component, this.log.<CATEGORY> prefixes each
                line with the instance (#id) — el.enableLogging(level?) makes one element louder
                or quieter than its type. Core never calls console directly: its own messages (invalid attribute
                values → INIT, actions / menus / twins → UI) go through the element's logger, or
                core's CORE bundle (ELEMENT / ACTIONS / MENU /
                THEME) for a tag with no bundle. The page-wide switch
                window.components.logging sets a level on every bundle, CORE included, and on
                bundles created later; a later per-tag call wins for that tag. The bundle controls never persist; only an
                explicit logger.setLevel(x) writes localStorage. The log below captures the
                console lines each button produced.

PG03 · The shared loader

            

                Components draw every loading state with
                renderLoader(host, container, context, { label, prefix }), which returns an idempotent
                remove(). Precedence, highest first: the instance
                renderLoadingCallback (same name in every component, read from the host), then the
                page-wide window.components.renderLoadingCallback, then the
                default <span class="<prefix>__loader" aria-hidden="true">, which the
                component draws with its own CSS — core ships none; the demo copies SPEC §12.14's drawing rule with
                --pgd-loader-* tokens chained to --base-loader-*. Only the highest present hook
                runs; a hook that throws is logged and the default is drawn instead, so a loading state is never blank.
                Hooks get { component, context, containerElement, element, label } and may return a cleanup.
                The container always gets role="status" (+ aria-label); remove()
                runs the cleanup, removes what the render added and restores the previous attributes. The page hook is a
                non-enumerable accessor shared by every bundled core copy; a plain value assigned before any component
                loaded is adopted.

What "throws" simulates

                A broken app hook — e.g. B's renderLoadingCallback calls a spinner library that didn't load,
                or looks up an element that isn't there. Core catches the error, logs
                renderLoadingCallback threw — drawing the default loader, removes anything the hook managed to
                add, and draws its default spinner, keeping role="status" + the label, so the
                user still sees (and a screen reader still announces) that B is loading. Note it falls back to the
                default, not to the page hook: only the highest hook that's set runs, so with "page hook"
                ticked, A shows the dots while B shows the default spinner.

stopLoading()  { this.#remove?.(); }

window.components.renderLoadingCallback = ({ component, context, containerElement }) => {
  containerElement.insertAdjacentHTML('beforeend', '<svg …>three animated dots</svg>');
};
// one instance — beats the page hook; the returned cleanup runs on remove()

  const timer = setInterval(tick, 100);
  return () => clearInterval(timer);

PG04 · Styles: adoptStyles() and an instance's custom CSS

            

                adoptStyles(root, ...css) is for a component's own, static CSS (the
                main.css?inline case): one cached CSSStyleSheet per unique string, shared by every
                instance through adoptedStyleSheets. Put that CSS in @layer component: adopted
                sheets cascade after every <style>, and only a layered rule loses to un-layered custom CSS.
            

            

                An instance's custom CSS is custom-styles (a CSS string) or getCustomStylesCallback(ctx)
                (CSS computed from the component's context; it wins when both are set). It lands in a
                <style>, so @import url(…) works. createCustomStyles() does this for a
                component, together with the page-wide layer in PG05. Only C changes here; D shows the shared sheet.
            

            

                
                
                
            

            

                

                    
                    
                

                

            

            
c.customStyles = '.pg { border: 4px solid #16a34a }';
c.getCustomStylesCallback = (ctx) => `.pg { background: ${ctx.tone === 'info' ? '#e0f2fe' : '#dcfce7'} }`;   // wins

// in the component
reinit() {
  adoptStyles(root, SHARED_CSS);                                          // '@layer component { … }'
  this.#styles ??= createCustomStyles(this, root, {
    cssClass: 'pgd-custom',
    getContext: () => ({ element: this, label: …, tone: … }),
    getInstanceStyles: () => ({ css: this.config.customStyles, callback: this.config.getCustomStylesCallback }),
  });
  this.#styles.refresh();
}
update(p) { if ('customStyles' in p || 'getCustomStylesCallback' in p) this.#styles.refresh(); }
destroyCallback() { this.#styles.destroy(); }

PG06 · Managed child: getOwner

            

                Some components mount another element and own it: web-dropzone's satellites belong to one store. The
                page styles the owner, so the child should look the same without being styled twice.
                The child's createCustomStyles() names its owner with getOwner, and the
                owner's page and instance layers, as the owner itself resolved them, land between the child's own:
                child page → owner page → owner instance → child instance.
            

            

                A later layer wins over an earlier one. A page write for either tag, or the owner's
                refresh(), refreshes the child too. No owner (getOwner returns
                null, throws, or the owner is gone from the page) means no owner layers, exactly as before.
            

            

                Try it. Each checkbox sets one layer. Every layer gives the child's card its own
                border colour and names itself under the card text, so the card always shows the layer that won. Tick
                them one by one in any order: the winner is always the latest layer in the chain above, not the last
                one you ticked. The readout lists the child's <style> slots in cascade order.
            

            

                
                
                
                
                
            

            

                
                

            

            
// in the child: its custom CSS names the owner
this.#customStyles = createCustomStyles(this, this.shadowRoot, {
  cssClass: 'pgc-custom',
  getContext: () => this.withContext({}),
  getInstanceStyles: () => ({ css: this.config.customStyles, callback: this.config.getCustomStylesCallback }),
  getOwner: () => this.#store?.host ?? null,   // read on every refresh; null = no owner layers
});

// the page styles the owner — its managed children follow
window.components['core-demo-pg-owner'].customStyles = '.pgc { border-color: #9333ea }';
owner.customStyles = '.pgc { border-color: #ea580c }';

        


        
        
        
        

            
PG07 · Locale and labels: window.components.locale

            

                Every UI string a component shows goes through core /locale's
                createLabels(host, DEFAULT_LABELS, () => this.config.labels, { tag }). Keys are flat
                <elementType>.<name> (buttons.remove); per key the instance
                labels (short or full key), then the page-wide flat dictionary
                window.components.locale.labels['<tag>.buttons.remove'] (the app's whole translation JSON
                fits), then the built-in English. An app with its own i18n sets translateCallback instead: it
                gets the full key and returns the text, or null to leave the key to core. A key the instance
                set is never sent to it. A dynamic text passes its context: .text(key, { ctx }), and the
                template reads {ctx.count}, {ctx.name} — dotted paths, numbers shown in the locale's
                format. ctx.count is the number the text's noun agrees with, so the app's i18n library pluralizes
                from it (core never does plurals): pick cs-CZ via translateCallback and step the file count —
                1 soubor / 3 soubory / 5 souborů. .text() is for textContent and attributes (never escaped),
                .html() for markup — the template is HTML, the context's values are data and are escaped;
                with window.components.security.shouldEscapeLabels the whole label is text.
                The locale, date pattern, 12 / 24 h clock, week start and number separators come from
                resolveLocaleSettings(): instance → page → Intl. Assigning the page object
                re-renders every live component through its localeChanged() hook. Element B has its own
                locale="de-DE" and one label of its own — those stay. Element C has its own
                translateCallback (Slovak, only buttons.remove): it is asked before the page-wide one,
                and its null leaves the other keys to the page — one element needs no page setup at all.
            

            

                The <i>Ann</i> in the title is on purpose: the user name is DATA ({ctx.user}), so .html() escapes it and you see the tags as text — while the template's own
                <b> around the count is markup and renders bold.

                    its NUMBERS and dates from its own locale="de-DE" — 12.345, DD.MM.YYYY,

                    A different language per element goes through translateCallback: it gets

PG08 · API summary

            

                
APIWhat it does

                
                    
registerComponent(tag, Class, { config, logging?, shouldAutoDefine? })Publishes window.components[tag] (adopting an existing entry), defines the element (unless shouldAutoDefine: false), wires the bundle to instance loggers. Returns the entry.

                    
entry.version() · config · logging · register() · getInstances()Build metadata, the bundle's controls (enableLogging / disableLogging / setLogLevel / resetLogging / setCategoryLevel / getCategories), idempotent define, live instances. Plus per-tag responsive / responsiveCallback (SPEC §6.7).

                    
getInstances(tag) · getConnectedTags()Connected elements of a tag (connection order); tags with at least one connected instance.

                    
createLoggers(namespace, categories?)A LoggerBundle: loggers, enableLogging(level = 'debug'), disableLogging(), setLogLevel(), resetLogging(), setCategoryLevel(), forInstance(). Nothing set → warn (DEFAULT_LOG_LEVEL).

                    
this.log.<CATEGORY>Protected instance loggers: [NS:CAT] #id; a tag with no bundle → [CORE:ELEMENT] tag#id.

                    
el.enableLogging(level?) · el.disableLogging() · el.resetLogging() · el.isLoggingEnabledThe element's own level; it wins over its type and the page (louder or quieter).

                    
window.components.logging / getPageLogging()The page level (enableLogging / disableLogging / setLogLevel / resetLogging / getCategories) for every bundle, CORE included, and later ones, wherever a type has no own level. Non-enumerable; state on globalThis.

                    
createPerfLogger(namespace)Opt-in timings through a NAMESPACE:PERF logger: start / end / measure / summary / clear. Records and prints only at debug or below.

                    
setLogPersistKeyPrefix(prefix) · getLogPersistKeyPrefix()The localStorage key prefix for levels saved by logger.setLevel(x): ${prefix}:${loggerName}, default km-log. Page-wide; existing loggers re-read their level.

                    
LOG_LEVELS · isLogLevel(x) · parseLogLevel(x)Level ranks (TRACE 0 … SILENT 5); is x a level name (either case) or rank; name or rank → rank (undefined if neither).

                    
coreLogging · getCoreLogging() · CORE_LOG_CATEGORIESCore's own bundle: CORE:ELEMENT / ACTIONS / MENU / THEME, created on first use (importing core has no side effect).

                    
renderLoader(host, container, context, { label, prefix, renderLoadingCallback? })Draws a loading state (instance hook > page hook > default span) and returns an idempotent remove().

                    
window.components.renderLoadingCallbackPage-wide loader hook (non-enumerable accessor; a non-function reads as unset).

                    
adoptStyles(root, ...css)A component's own static CSS: shared, cached constructable sheets, deduplicated per root. Keep it in @layer component so custom CSS can override it.

                    
createStyleElement(root, { position?, cssClass? })A replaceable per-instance <style>: set(css) / clear() / destroy(), read-only element.

                    
createCustomStyles(host, root, { getContext, getInstanceStyles, cssClass?, position?, onApply?, shouldHoistImports?, getOwner? })Custom CSS for a component: the page layer, then the instance layer, each a <style> (callback wins over CSS). Returns { refresh, destroy }; follows page changes until destroy().

                    
shouldHoistImportsAlso links each custom-CSS @import URL in the document <head> (shared, ref-counted; a <link> the page already has is reused), so an imported @font-face registers — Chromium ignores it inside a shadow root. Default true, only for a shadow root. The page wins: window.components[tag].shouldHoistImports, else window.components.shouldHoistImports (false when the page loads those fonts itself).

                    
getOwner: () => HTMLElement | nullA managed child's owner (PG06), read on every refresh. The owner's page and instance layers, as the owner's own handle resolved them, sit between the child's: child page → owner page → owner instance → child instance (slots <cssClass>--owner-page, <cssClass>--owner). A page write for either tag or the owner's refresh() refreshes the child. null, a throw (logged), an owner with no live handle or one removed from the page = no owner layers.

                    
window.components.locale · window.components.securityPage-wide locale settings, ONE flat labels dictionary ('<tag>.<elementType>.<name>'), translateCallback (gets params.ctx), parseNumberCallback; shouldEscapeLabels. Non-enumerable; assigning replaces the object (stored frozen) and re-renders every component (localeChanged()).

                    
createLabels(host, defaults, getOwn, { tag, getLocale }) (/locale){ template, text, html, all } — instance → the element's then the page's translateCallback → page labels['<tag>.<key>'] → English; values as { ctx }, templates {ctx.count}; text never escaped, html escapes the values (or everything with shouldEscapeLabels).

                    
resolveLocaleSettings(instance) · resolveLocale · getMonthNames · formatNumber · parseNumberPer key instance → page → Intl: locale, date pattern, 12 / 24 h, week start, separators; month / weekday names; numbers with the resolved separators.

                    
window.components[tag].customStyles / .getCustomStylesCallback(ctx)Page layer for every instance of the tag, before the instance's own custom CSS. The callback gets each instance's context and, while set, replaces customStyles. Installed by registerComponent() (a value set on a pre-created entry is adopted); assigning updates the live instances; a wrong type warns and keeps the previous value.
