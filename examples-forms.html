FO01 · Form association and el.form

A form-associated custom element takes part in its form, but unlike a native control it gets no .form property for free: the browser keeps the association inside ElementInternals. Core re-exposes it as el.form (read through the lazily attached, protected internals — a subclass must never call attachInternals() itself). Unlike closest('form'), it honours the form="id" attribute, so event.target.form resolves for frameworks that route by it (Phoenix LiveView's phx-change). The submitted data comes from the hidden <input name> each field renders in its light DOM; the field outside the form copies its form attribute onto that input (component code). Core implements no formResetCallback — the demo field has its own, returning to its value attribute like a native input.

Where an element sits and which form it belongs to are two different things. closest('form') only looks at the DOM, so it gives null for Extra. The browser goes by the form the element is a member of: the <form> it's nested in, or the one named by its form="id" attribute. So FormData, submit and reset all include Extra, as they would a native <input form="…"> placed anywhere on the page.

FO02 · Disabled: isDisabled and <fieldset disabled>

            

                An element can be disabled two ways: its own disabled attribute
                (el.isDisabled), or a disabled <fieldset> around it, which the browser
                reports only through formDisabledCallback. Core implements that callback for every component
                and combines both into isEffectivelyDisabled. A component never writes
                formDisabledCallback. It reads isEffectivelyDisabled in reinit() and
                gets disabledChanged(isDisabled) whenever the combined state flips on a built element (a
                rebuild reads it in reinit() instead).
            

            

                The fieldset never writes el.isDisabled. The protected isFormDisabled reports
                the fieldset side alone. The native :disabled pseudo-class matches either way.
            

            

                isDisabled must reflect (a property write is copied to the attribute).
                The browser decides "disabled" from the host's disabled attribute, not from the property.
                So for <core-demo-field disabled>, el.isDisabled = false has to remove
                the attribute too. Otherwise the component draws itself enabled while the browser still blocks it.
                The input-table check warns when a component's isDisabled doesn't reflect.
            

            

                The host's disabled attribute doesn't disable its children, so the demo disables its
                light-DOM hidden input itself, in disabledChanged.

FO03 · Validity and setFormatError()

            

                A form-associated class gets the standard constraint-validation API, read through
                internals: validity, validationMessage, willValidate,
                checkValidity() (fires the cancelable invalid event when invalid) and
                reportValidity() (also shows the browser's bubble). The protected
                setFormatError(error, message?, anchor?) marks the host invalid (customError)
                when the component could not produce a value. The message is message, else the error's own
                message, else "The value is invalid."; anchor, a descendant such as the visible
                input, positions the bubble (an anchor the browser rejects is dropped with a warning). null
                clears it, and clears all validity flags. While invalid, :invalid matches and the form
                fires invalid instead of submit — unless it is <form novalidate>.
                Type something that isn't a whole number (abc) into either field, then submit both.
                The buttons call setFormatError() directly and override the field's own check until the next
                keystroke. So after setFormatError(null) the field can still hold abc and its hint
                still says invalid, while the readout says valid.

FO04 · API summary

            

                
MemberKindWhat it does

                
                    
static formAssociated = trueclass opt-inMakes the host a form-associated element; enables everything below.

                    
internalsprotected getterThe element's ElementInternals, attached lazily and memoized (null where unavailable). Never call attachInternals() yourself.

                    
formgetterThe associated <form> or null — honours form="id" and shadow boundaries. Always null when not form-associated (even inside a <form>).

                    
formDisabledCallback(isDisabled)browser callbackImplemented once by core: records the browser's combined state, flushes pending writes, fires disabledChanged on a flip. Don't override.

                    
isDisabled / disabledinput / attributeThe component's own disabled flag (conventional configKey, read by isEffectivelyDisabled). Must have shouldReflect: true: the browser disables the host by its disabled attribute, so el.isDisabled = false has to remove it (the input-table check warns otherwise).

                    
isFormDisabledprotected getterDisabled by an ancestor <fieldset disabled> only (outside its first <legend>).

                    
isEffectivelyDisabledprotected getterisDisabled || isFormDisabled — read it in reinit().

                    
disabledChanged(isDisabled)protected hookThe effective state flipped on a built element (input or fieldset). Not called for a rebuild or before the first build.

                    
validity · validationMessage · willValidategettersFrom internals; "no constraint" answers (undefined / '' / false) when not form-associated.

                    
checkValidity() · reportValidity()methodsLike a native control (invalid event; the bubble for reportValidity). true when not form-associated.

                    
setFormatError(error | null, message?, anchor?)protected methodNon-null → customError with the resolved message (anchor positions the bubble; an anchor the browser rejects is dropped with a warning); null → valid (clears all flags). No-op when not form-associated.

                    
formResetCallback()browser callbackNot implemented by core: what "reset" means is the component's call. The demo field returns to its value attribute, like a native input (FO01).

                
            

            

                
What core leaves to the component

                Submission (Keenmate components render light-DOM hidden inputs named by name, with a
                value-format, rather than internals.setFormValue()), formResetCallback,
                formStateRestoreCallback, and any validity constraint other than the format error (set through
                internals directly — setFormatError(null) clears every flag).
