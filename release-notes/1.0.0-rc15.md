# Web Components Core 1.0.0-rc15 — Release Notes

**Released:** 2026-10-31 · **Pre-release** (`npm install @keenmate/web-components-core@rc`)

rc15 is the foundation of the KeenMate **v2 component generation**. Three things happened since
rc14: one **interaction model** for every component (events, `on*` twins, before-callbacks,
clickable items, the shared menu), one **lifecycle** (`defer` / `ready` / `destroy()` /
fieldset-aware disabled / form validity), and a **naming review** that brought the whole public API
to the house conventions. It also adds the shared loader (`renderLoader()`), live property getters
(`getLiveValue`) and a long list of robustness fixes.

**Upgrading needs action.** rc15 is a breaking release for component authors: names changed with no
aliases, `on<Name>` properties receive the detail, events no longer cross shadow roots, and `ready`
fires on a microtask. Pages that only *use* components get these changes through the components' own
v2 releases, which are built on this core.

The exhaustive, per-change list is in [`CHANGELOG.md`](https://github.com/KeenMate/web-components-core/blob/v1.0.0-rc15/CHANGELOG.md#100-rc15---2026-10-31);
this document is the upgrade guide and the highlights.

## Upgrade checklist

**Everyone (pages using core-based components)**

- [ ] `el.onFoo = (d) => …` receives the **detail**, not the event ([details](#interaction-model)).
- [ ] Listening for a component event from *outside* an enclosing shadow root? Events are no longer
      `composed` ([details](#interaction-model)).
- [ ] Code reading `isReady` synchronously after append must `await el.whenReady()` ([details](#ready-is-asynchronous)).
- [ ] Page-wide menu styling now works via `--km-menu-*` (was `--bliss-menu-*`) ([details](#renames)).

**Component authors**

- [ ] Apply the [renames](#renames) — no aliases.
- [ ] Drop your own `defer` / `ready()` / `is-ready` / `data-ready` gate; core's `defer` / `ready` replaces it ([details](#lifecycle)).
- [ ] Move teardown into `destroyCallback()`; hand-written `formDisabledCallback` onto `isEffectivelyDisabled` + `disabledChanged()`.
- [ ] Make the `isDisabled` input (attribute `disabled`) **reflect** — core warns otherwise ([details](#isdisabled-must-reflect)).
- [ ] Map menu variables onto the private `--_km-menu-*` only; leave your own menu variables unset by default ([details](#page-wide-menu-theming)).
- [ ] Draw every loading state with `renderLoader()` and add a `renderLoadingCallback` input ([details](#shared-loader)).
- [ ] Rename the `mobile-presentation` input to `presentation` (type `Presentation`); `resolveMobilePresentation()` is gone ([details](#renames)).
- [ ] Export `<Name>ResponsiveMap` / `<Name>ResponsiveCallback` aliases over your config type ([details](#responsive-rules)).
- [ ] Listeners that read pre-action state in the `action` event take it from the detail (`row`, `node`, …) — the built-in already ran ([details](#action-order)).

## Breaking changes

### Interaction model

| Before | After |
|---|---|
| `el.onSelect = (e) => e.detail.option` — a listener | `el.onSelect = (d) => d.option` — the event's **twin**, called with the detail by `emit()`, then the DOM event fires with the same object |
| events `bubbles: true, composed: true` | `bubbles: true, composed: false` — pass `composed: true` per call / `EventDef` where crossing is intended |
| `emit('x')` delivered `detail: undefined` | `{}` + the component context (`controller`, `element`, non-enumerable, + `eventContext()` extras) |
| `searchCallback(term, signal, context)` | `searchCallback(ctx)` — `SearchCallbackContext { term, signal, entries }`, one `term` (the prepared one) |
| `SearchEntry.item` | `SearchEntry.data` |

### Action order

`runAction`: `beforeActionCallback` (veto) → item `onClick` → **built-in** → `action` event + `onAction`
twin. The event used to fire *before* the built-in. It is now a notification after the fact (after
web-grid `delete`, the row is gone from `items`). To prevent a built-in, return `false` from
`beforeActionCallback`. A throwing built-in is logged, and the event still fires.

### Ready is asynchronous

The `ready` event, the `ready` attribute / `:state(ready)`, `isReady` and `whenReady()` flip on the
**microtask** after the first build + `connect()`. A listener added right after `createElement` now
catches it. A microtask was chosen instead of rAF because rAF stalls in hidden tabs.

### `isDisabled` must reflect

The browser disables a form-associated host by its own `disabled` attribute, so a non-reflecting
`isDisabled` got stuck. `isFormDisabled` now reports the `<fieldset>` side only. The input-table check
warns on a form-associated class whose `disabled` input doesn't reflect.

### Invalid attribute values keep the previous value

`el.setAttribute('page-size', 'abc')` warns and keeps `25` (it used to reset silently to the default),
which is the same rule as the property path. Reflected inputs write their value back. Removing the
attribute still resets it to the default. Converters report bad strings via the new 4th
`fromAttribute` argument, `reportInvalid(reason?)`.

### Renames

| Where | Old | New |
|---|---|---|
| element | `el.defer` | `el.shouldDefer` (attribute stays `defer`) |
| `InputDef` | `reflect` | `shouldReflect` |
| `BlissElement` | `static themeContext` / `resized()` / `isRTL` | `hasThemeContext` / `sizeChanged()` / `isRtl` |
| `runHook` | `onError` | `errorCallback` |
| before-callbacks | `BeforeCallbackResult.isCancelled` | `isRejected` |
| `/actions` | `isActive`, `getIsActiveCallback`, `__item--active` | `isToggled`, `getIsToggledCallback`, `__item--toggled` (menu: `menuitemcheckbox` + `aria-checked`) |
| `/menu` | `.bliss-menu*`, `--bliss-menu-*` | `.km-menu*`, `--km-menu-*` |
| `/menu` `openMenu` | `onClose`, `className` | `closeCallback`, `cssClass` |
| `/dom` `createStyleSlot` | `className` | `cssClass` |
| `/positioning` | `flip`, `autoUpdate`, `fixedContainingBlock` | `shouldFlip`, `shouldAutoUpdate`, `shouldUseFixedContainingBlock` |
| `/positioning` callbacks | `beforeCompute`/`onBeforeCompute`, `onPlaced`, `onComputed`, `onDrift`, tooltip `onBeforeShow` | `beforeComputeCallback`, `placedCallback`, `computedCallback`, `driftCallback`, `beforeShowCallback` |
| `createTooltip` | `followCursor` | `shouldFollowCursor` |
| environment observers | `immediate`, `ObserveOptions` | `shouldFireImmediately`, `ObserveEnvironmentOptions` |
| overlay | `km-overlay-activated`, `OVERLAY_ACTIVATED_EVENT`, `dispose()`, `presentationContext()` | `km-overlay-activate`, `OVERLAY_ACTIVATE_EVENT`, `destroy()`, `createPresentationContext()` |
| `/search` | `prepare`, `onObjectTerm` | `getSearchTermCallback`, `objectTermCallback` |
| misc | `declaredCssVars()`, `caseInsensitive` | `extractDeclaredCssVars()`, `isCaseInsensitive` |
| overlay | `MobilePresentation`, `resolveMobilePresentation()` | `Presentation`, `resolvePresentation()` |

### Breakpoint default

The default `mobile` width bucket is now `≤ 768` (was `≤ 640`), matching pure-css; the page can move
it with `--base-breakpoint-mobile` / `--base-breakpoint-tablet`. `classifyDevice()` is unchanged.

Components that bundle an older core keep `km-overlay-activated`, so on a mixed-version page their
overlays won't close each other's until all of them are rebuilt.

### Page-wide menu theming

Every menu value reads `var(--_km-menu-X, var(--km-menu-X, var(--base-…, <default>)))`. Components
set only the private `--_km-menu-*`. The old `:host { --km-menu-bg: var(--wtv-…) }` mapping shadowed
page-level `--km-menu-*`, so menu theming never reached menus inside a component.

## New features

### Responsive rules

Partial configs per device class / width breakpoint, page-wide (`window.components.responsive` /
`responsiveCallback`), per tag (`window.components['web-x'].responsive` / `responsiveCallback`) and
per instance (`el.responsive` + JSON attribute, `el.responsiveCallback`). Precedence: page rules <
anything set on the element < the element's own rules; an instance `null` ignores the page rules.
Overrides never reflect; `config` is the effective config, `ctx.config` the base. Re-run on
environment flips and rule changes (callbacks also on every throttled viewport-size change), diffed,
one batch. See SPEC §6.7.

A map has two explicit axes — `device` (keyed by `classifyDevice`: capability first, then the short
side; a mouse device is `desktop` at any width) and `breakpoint` (keyed by the window-width bucket,
768 / 1024 lines). Within one map the breakpoint entry applies first and the device entry over it
(device wins on the same key); then that level's callback. Any other top-level key (a device-keyed
`{ mobile: … }` map) warns once per element and is ignored.

```js
window.components['web-treeview'].responsive = {
  device:     { mobile: { shouldAlignNodeIcons: false }, tablet: { shouldAlignNodeIcons: true } },
  breakpoint: { mobile: { shouldAlignNodeIcons: false } },
};
// own widths / combinations → callback
window.components['web-treeview'].responsiveCallback = ({ deviceClass, env }) =>
  deviceClass === 'desktop' && env.viewportWidth < 600 ? { shouldAlignNodeIcons: false } : undefined;
```

| Situation | deviceClass | breakpoint | Result |
|---|---|---|---|
| Phone | `mobile` | `mobile` | `device.mobile` → `false` |
| Desktop window narrowed below 768 px | `desktop` | `mobile` | `breakpoint.mobile` → `false` |
| iPad portrait (768 wide) | `tablet` | `mobile` | `device.tablet` beats `breakpoint.mobile` → `true` |

The JSON attribute takes the same shape: `responsive='{"breakpoint":{"mobile":{…}}}'`.

### Lifecycle

| API | What it does |
|---|---|
| `defer` attr / `shouldDefer` + `release()` | hold the first build while options, callbacks and listeners are wired; latched |
| `ready` event / attr / `:state(ready)`, `isReady`, `whenReady()` | announced once after the first live build |
| `destroy()` / `destroyCallback()` / `isDestroyed` | final teardown; the element is inert afterwards |
| `removedCallback()` | fires when the element is still detached at the next frame (a real removal, not a move); opt-in |
| `isFormDisabled`, `isEffectivelyDisabled`, `disabledChanged(isDisabled)` | core implements `formDisabledCallback` once |

### Form validity

Form-associated classes get `validity`, `validationMessage`, `willValidate`, `checkValidity()` and
`reportValidity()`. The protected `setFormatError(error | null, message?, anchor?)` marks the host
invalid (`customError`) when a component can't produce its value, e.g. a throwing
`getValueFormatCallback`. This blocks submit unless `<form novalidate>`; `null` clears it.

### Live property getters

```ts
{ configKey: 'nodes', converter: toValue(), on: 'reinit',
  getLiveValue: (el) => el.getLiveNodes() }   // el.nodes returns the live tree after the build
```

The getter returns live state once the element has built. Before the build, while a write is
staged, after a failed `reinit()`, or when the callback returns `undefined`, it returns the stored
value. The setter path and `this.config` are unchanged.

### Shared loader

```ts
const remove = renderLoader(this, overlayEl, 'overlay', { label: labels.loading, prefix: 'wtv' });
// … later
remove();
```

Precedence: instance `renderLoadingCallback` > page-wide `window.components.renderLoaderCallback` >
default `<span class="<prefix>-loader">`. The container gets `role="status"` + `aria-label`. The
callback ctx is `{ component, context, containerElement, element, label }` and may return a cleanup
function. Core ships no loader CSS: copy the drawing rule from SPEC §12.14 and chain the
`--<prefix>-loader-*` tokens to `--base-loader-*`.

### `/actions` and `/menu`

- **`/actions`**: `ActionItem` / `MenuItem` / `MenuDivider`, `resolveActionItem`, `menuDivider()` and
  `runAction` (fixed order, busy guard). Before-callbacks use `runBeforeCallback` /
  `runBeforeCallbackSync` / `runBeforeCallbackEager`: `false` rejects, a value replaces, and a throw
  rejects (logged).
- **`/menu`** `openMenu(entries, ctx, opts)`: submenus (incl. lazy children), positioning via
  `/positioning`, dismiss rules, overlay coordination and the WAI-ARIA menu keyboard model. It is
  styled by `--km-menu-*` → `--base-*`, and the `--km-menu-*` list ships as
  `component-variables.manifest.json`.

### More

- **`InputDef.getBatchValuesCallback`**: an input that sets others in the same batch (presets such as
  web-grid's `mode`). Inputs set explicitly in that batch win.
- **`BlissElement`**: `controller` + `createController()`, `eventContext()`, `withContext()`;
  `withComponentContext`, `ComponentContext` and `EmitDetail` are exported.
- **Logging**: `window.components.logging` is the page-wide switch (`enableLogging` /
  `disableLogging` / `setLogLevel` / `getCategories`). `setCategoryLevel` accepts `'GRID:DATA'`.
- **CEM**: `blissInputsPlugin()` documents the core-declared inputs in every manifest — `defer`,
  `theme-source`, `responsive` / `responsiveCallback` and the `ready` event (regenerate your CEM).
- **`anchor()` `offset`** takes `{ mainAxis, crossAxis, alignmentAxis }`; there is a new
  `--km-menu-hover-color`.

## Visible changes without a migration

- **Default log level is `warn`** for every bundle. Core's own messages (input validation, actions,
  menus, twins, theme) go through loggers, so `disableLogging()` silences them too.
- Log lines read `[MULTISELECT:UI] #country  <message>`.
- `--km-menu-disabled-opacity` defaults to `0.65` (was `0.5`), the base contract value.

## Fixes

- A throwing `reinit()` / `update()` no longer wedges the element: `whenSettled()` resolves, a failed
  `reinit()` is retried, and `connect()` waits for a successful build.
- A row's `default` applies when the converter has none (`toInt()` + `default: 5` used to be `undefined`).
- `toEnum({ shouldNullOnInvalid })` accepts `el.x = null`.
- A rejected pre-upgrade property no longer blocks the initial attribute.
- `toList` / `toObjectArray` defaults are no longer shared between instances.
- `toValue` reflection removes the attribute for a function value instead of writing `"undefined"`.
- `anchor()` ignores a position that resolves after `destroy()`. The fixed-containing-block detection
  now matches Floating UI.
- `data-theme` inheritance for portaled layers crosses shadow roots.
- `observeKeyboardInset` cleanup cancels a queued frame. A stale environment snapshot is no longer
  re-cached.
- `findHighlightRanges` no longer returns overlapping ranges for `ß`.
- `mount(html, { container })` returns the mounted element.
- `lockBodyScroll()` before `<body>` is now a no-op.
- `el.form` returns `null` on an element that isn't form-associated — a real browser used to throw.
- `setAttributes()` warns about a key that isn't an input instead of skipping it silently (a renamed
  `data` → `nodes` once left a page with an empty tree and no error); the core-declared `shouldDefer`,
  `themeSource`, `responsive` and `responsiveCallback` are now accepted there.
- A throwing `observeEnvironment` / `observeViewport` / `observeThemeContext` listener is logged and no
  longer stops the other listeners.
