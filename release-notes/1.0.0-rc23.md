# Web Components Core 1.0.0-rc23 — Release Notes

**Released:** 2026-11-13 · **Pre-release** (`npm install @keenmate/web-components-core@rc`)

rc23 fixes a phone bug found in the rc22 demo: closing a menu's bottom sheet scrolled the page to the top.
The phone Back gesture behind it becomes one core helper, `claimBackEntry()`, which replaces the copies in
web-grid, web-multiselect and web-daterangepicker. **Upgrading needs no code change** unless a test
reads the sheet's `history.state`.

The exhaustive list is in [`CHANGELOG.md`](https://github.com/KeenMate/web-components-core/blob/v1.0.0-rc23/CHANGELOG.md#100-rc23---2026-11-13).

## Upgrade checklist

**Component authors**

- [ ] Bump to `^1.0.0-rc23`.
- [ ] A phone sheet / modal that closes on the Back gesture: replace your own `history.pushState()` +
      `popstate` listener with `claimBackEntry()` ([details](#claimbackentry-the-phone-back-gesture)).
      Rulebook C-RO-15 flags the old pattern.
- [ ] Tests that read the sheet's history entry: `history.state` is now `{ kmBackEntry: true }`
      (the menu's was `{ kmMenuSheet: true }`).

## Behaviour changes

### One history entry name

The menu sheet's history entry is now `{ kmBackEntry: true }` (was `{ kmMenuSheet: true }`), shared by
every component that uses `claimBackEntry()`. Only code that inspects `history.state` notices.

## New features

### `claimBackEntry()`: the phone Back gesture

```ts
import { claimBackEntry, lockBodyScroll, observeKeyboardInset } from '@keenmate/web-components-core';

// on open (full-screen / modal tier)
const unlock = lockBodyScroll();
const unobserve = observeKeyboardInset(panel);
const releaseBack = claimBackEntry(() => this.close('back'));   // phone Back closes it

// on every close (✕, Escape, a pick, Back — releasing twice is a no-op)
releaseBack();
unobserve();
unlock();
```

- One history entry (same URL) for the whole page while a sheet is open. Back runs the newest claim's
  `onBack`; claiming again from inside `onBack` re-arms the entry (one submenu level up, the sheet stays).
- A release gives the entry back with `history.back()` one task later, so a sheet that opens right after
  takes it over instead of racing a `back()` against a new `pushState()`.
- The page keeps its scroll position (see [Fixes](#fixes)).
- Page-wide state, shared by every copy of core on the page. Was `/menu`'s private helper;
  web-grid, web-multiselect and web-daterangepicker each had their own copy (per instance or page-wide,
  closing at once or deferred) and now use this one.

## Fixes

- **Closing a phone sheet no longer scrolls the page to the top.** A sheet locks page scroll first
  (`lockBodyScroll()` pins `<body>`, so the window's scroll is 0) and then pushes its Back entry, so the
  browser recorded 0 for the page's entry. When the entry was given back (close button, backdrop,
  Escape, an item) or popped (Back), the browser restored that 0 after the scroll lock had put the page
  back. Seen in the menu sheet and web-daterangepicker's sheet and modal. While an entry is held the
  page's entry now uses `history.scrollRestoration = 'manual'`, and gets its own mode back one task after
  it is current again (the browser restores scroll after `popstate` and reads the mode then).
