# Web Components Core 1.0.0-rc20 — Release Notes

**Released:** 2026-11-08 · **Pre-release** (`npm install @keenmate/web-components-core@rc`)

rc20 closes the gaps the first component alignment (web-treeview) and a sweep of every component
found in core itself: fonts in custom CSS, values set before a component loads, overlay and menu
dismissal, the phone scroll lock and the theme on portaled panels. Each is a place where core
didn't keep its own promise or contradicted itself; nothing was copied in from a component.

**Upgrading needs no code change.** Pages and components get the fixes by bumping the dependency.
Three behaviour changes are worth a test run (menus and scroll, the new warnings, the `<html>`
scroll lock), and pure-css has two small ports.

The exhaustive, per-change list is in [`CHANGELOG.md`](https://github.com/KeenMate/web-components-core/blob/v1.0.0-rc20/CHANGELOG.md#100-rc20---2026-11-08);
this document is the upgrade guide and the highlights.

## Upgrade checklist

**Component authors**

- [ ] Bump to `^1.0.0-rc20`, then run your tests. Menus no longer close on an unrelated scroll or a
      bare mouse wheel ([details](#openmenu-closes-on-scroll-by-the-popover-rule)).
- [ ] Watch the console for the two new warnings: an input named like one of your class members
      ([details](#input-table-check-dead-class-members)), and a page `customStyles` your component
      never applies ([details](#custom-css-one-adoption-for-every-component)).
- [ ] Adopt `createCustomStyles()` the canonical way if you haven't (rulebook C-CA-15), and drop any
      own custom-style code, `@import` / font handling included.
- [ ] Drop your own pre-upgrade rescue code for `value` / `items` / … ([details](#values-set-before-a-component-loads-are-kept)),
      and your own `<html>` `overflow-x` clamp around a sheet ([details](#the-scroll-lock-also-locks-html-sideways)).
- [ ] Optional: style a portaled panel with `[data-context-theme="dark"]` ([details](#portaled-panels-keep-the-components-theme-and-motion)).

**Pages**

- [ ] Loading your icon fonts yourself? `window.components.shouldHoistImports = false`
      ([details](#custom-css-imported-fonts-work-in-a-shadow-root)).

**pure-css**

- [ ] Port the `ScrollLockState.saved.rootStyle` field and the `<html>` `overflow-x` lock, and the two
      attributes `anchor()` now inherits (entries marked *pure-css port affected* in the CHANGELOG).

## New features

### Custom CSS: imported fonts work in a shadow root

Chromium ignores `@font-face` inside a shadow root, so an icon font imported through custom CSS drew
boxes. `createCustomStyles()` now also links each `@import` in the document `<head>`:

| Behaviour | |
|---|---|
| Shared | one `<link data-km-custom-styles>` per URL for the whole page, ref-counted across instances and core copies |
| Released | when the last instance stops importing it, is `destroy()`ed, or is really removed from the page (a move keeps it; re-attached, it takes it back) |
| Conditions kept | an import with `layer()` / `supports()` / media goes in as a head `<style>` holding the whole statement |
| Only real imports | the leading `@import`s of each layer; a commented-out or late one is ignored, as the browser does |
| Page-owned | a stylesheet the page already links is reused and never removed |

The page decides:

```js
window.components.shouldHoistImports = false;                 // every component on the page
window.components['web-treeview'].shouldHoistImports = true;   // one component type (wins)
```

CSP: the URL was already loaded by the `@import` inside the component (same `style-src`); a
conditional import's head `<style>` is inline, like every custom-CSS slot already is.

### Custom CSS: one adoption for every component

`docs/usage.md` → "Style injection" shows the one way to adopt `createCustomStyles()`: the input rows
`customStyles` (`custom-styles`) and `getCustomStylesCallback`, one handle (`cssClass:
'<prefix>-custom-styles'`, core's default position), refreshed per build and on those keys, destroyed
in `destroyCallback()`. Rulebook check **C-CA-15** enforces it. Core warns once per component type when
a page sets `window.components[tag].customStyles` for a component that never applies it.

### Values set before a component loads are kept

`el.value = ['cz']` on an element whose script hasn't loaded stores a plain property that hides the
component's setter. Core rescued only input-table properties and `on*` handlers; it now lifts every
early property that shadows a getter / setter of the component's class and replays it through that
setter before the first build. A read-only one is dropped with a warning.

## Visible changes without a migration

### `openMenu()` closes on scroll by the popover rule

One shared helper (`watchScrollClose()`) now decides for both `createPopover()` and `openMenu()`: only
a scroll of the page or of a scroller around what the layer belongs to, once that actually moved;
never a scroll inside it. Menus (web-treeview, web-grid, web-editor) no longer close on an unrelated
scroller, a late scroll event or a bare mouse wheel.

### Input-table check: dead class members

An input whose `configKey` names a getter / setter / method of the component class replaced that
member silently (web-grid has 64). The once-per-class table check now warns; live state belongs in
the row's `getLiveValue`. The SPEC also records that core hooks stay `protected` in a component —
writing many inputs at once is `setAttributes()` / `batch()` (rulebook C-CA-14).

### The scroll lock also locks `<html>` sideways

`lockBodyScroll()` sets `overflow-x: hidden` on `<html>` while held and restores its inline value on
the last release, so a page wider than a phone screen doesn't stay zoomed out under a fullscreen sheet.
`ScrollLockState.saved` gains an optional `rootStyle`; a joiner without it leaves `<html>` alone.

### Portaled panels keep the component's theme and motion

`anchor()`'s `inheritThemeFrom` also copies `data-context-theme` (the effective scheme: Tailwind
`.dark`, `setThemeMode()`, `theme-source`) and `data-motion` onto the panel, restored on `destroy()`.

## Fixes

- **A stopped click closes overlays again.** rc19 decided an outside click on a `window` bubble
  listener, so a click whose propagation a handler stopped (web-treeview's checkbox) closed nothing,
  and the recorded press lingered until a later keyboard click. The router now sees the click on the
  way down and decides a stopped one once its task is done.
- **`createPopover()` closes when its reference leaves the page** (`'reference-removed'`), like the
  tooltip already did — a re-rendered row no longer leaves the panel at stale coordinates.
