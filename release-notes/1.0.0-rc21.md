# Web Components Core 1.0.0-rc21 — Release Notes

**Released:** 2026-11-10 · **Pre-release** (`npm install @keenmate/web-components-core@rc`)

rc21 comes from aligning all seven components with core (web-treeview, web-multiselect,
web-daterangepicker, web-commandpalette, web-dropzone, web-grid, web-editor) and validating every one of
them against this build before release: scroll-close fixes for WebKit and Firefox, context menus that
follow the component's own scroller, deterministic and more complete `/cem` output, two helpers on the
main index, and the SPEC rule for disabled / readonly. **Upgrading needs no code change.**

The exhaustive list is in [`CHANGELOG.md`](https://github.com/KeenMate/web-components-core/blob/v1.0.0-rc21/CHANGELOG.md#100-rc21---2026-11-10).

## Upgrade checklist

**Component authors**

- [ ] Bump to `^1.0.0-rc21`.
- [ ] Delete your own manifest line-ending / module-order plugin; `blissAnalyzerConfig()` does it now ([details](#cem-deterministic-manifest-output)).
- [ ] Replace private copies of `deepActiveElement()` / `escapeHtml()` with the core imports ([details](#deepactiveelement-and-escapehtml-on-the-main-index)).
- [ ] Shared input rows imported from a sibling module now reach the manifest — regenerate it ([details](#cem-shared-input-rows-from-a-sibling-module)).
- [ ] Persisting UI state? Use `createStateStore()` with the rows `storageKey` / `loadStateCallback` / `saveStateCallback`; no own `localStorage` code (rulebook C-CA-17) ([details](#persisted-ui-state-one-way-createstatestore)).
- [ ] A virtual list: replace your own index → `scrollTop` math with `scrollContainerToBox()` / `getScrollTopForBox()` ([details](#scroll-to-a-row-that-isnt-rendered-scrollcontainertobox)).
- [ ] Delete your hard-coded field → panel `offset` (dropdown, calendar, popover); core reads `--base-dropdown-offset` ([details](#one-field--panel-gap---base-dropdown-offset)).

**Pages**

- [ ] Want a different gap between fields and their panels? Set `--base-dropdown-offset` on `:root`, a section, or a component tag ([details](#one-field--panel-gap---base-dropdown-offset)).
- [ ] A data-input component: make sure it has both `isDisabled` and `isReadonly` ([details](#examples-and-docs)).

## New features

### `/cem`: deterministic manifest output

`blissAnalyzerConfig()` runs `stableOutputPlugin()` right after the inputs plugin and before your own
plugins, so the editor-integration generators read the stable form:

| | |
|---|---|
| Line endings | every manifest string converted to LF (a CRLF checkout no longer rewrites the files) |
| Module order | sorted by path (the analyzer's order varied from run to run) |

`stabilizeManifest(manifest)` is exported for a custom pipeline.

### One field → panel gap: `--base-dropdown-offset`

`anchor()` — and so `createPopover()` and an `openMenu()` dropped from an element — uses the page token
`--base-dropdown-offset` (`@keenmate/base-css-variables` 2.0.1, `4px`) as its default `offset`, read on the
reference element when the panel is anchored. web-multiselect used 4px and the web-daterangepicker calendar 8px,
so one form had two gaps; components now pass no offset. The token inherits:

```css
:root { --base-dropdown-offset: 6px; }               /* every panel on the page */
web-daterangepicker { --base-dropdown-offset: 8px; } /* one component type */
```

An explicit `offset` still wins. Tooltips keep 8px, a right-click (point) menu 0.

### Persisted UI state, one way: `createStateStore()`

What the user arranged — a popover's size, column widths / order, favorites — was kept three ways
(web-dropzone `persistStateCallback`, web-grid localStorage only, web-commandpalette `usage-key`). SPEC
§12.17 makes it one: three input rows and one handle.

| Input | |
|---|---|
| `storage-key` (`storageKey`) | the key; unset = off |
| `loadStateCallback(ctx & { key })` | set → the host keeps the state (per user, on the server) |
| `saveStateCallback(ctx & { key, state })` | gets the WHOLE state on every save |

```js
#state = createStateStore(this, {
  getKey: () => this.config.storageKey,
  getLoadCallback: () => this.config.loadStateCallback,
  getSaveCallback: () => this.config.saveStateCallback,
  toContext: (data) => this.withContext(data),
});
```

Default store `localStorage['km-state:<tag>:<key>']`; failures are logged, never thrown.

### Scroll to a row that isn't rendered: `scrollContainerToBox()`

`scrollIntoContainer(el)` needs a rendered element, so a virtual list's index jump (`scrollToIndex()`,
PageUp / PageDown) did its own math — web-multiselect, web-treeview and web-grid each had a copy. The
target is now a box in the list's content coordinates, with the same block rules and `scroll-padding`:

```js
import { scrollContainerToBox, getScrollTopForBox } from '@keenmate/web-components-core';

scrollContainerToBox(list, { top: index * rowHeight, height: rowHeight }, { block: 'center' });
// a grid with a sticky header measured in JS, rendering its window before it scrolls:
const top = getScrollTopForBox(body, { top: i * h, height: h }, { block: 'start', insetTop: theadHeight });
```

`behavior: 'auto'` (default) sets `scrollTop` synchronously, so the list renders the new window right
after; both return `null` when nothing has to move.

### `/cem`: shared input rows from a sibling module

`static inputs = [...SHARED_ROWS, …]` with `SHARED_ROWS` imported from a relative module
(`./satellite-base.js`) used to be only a build warning, and the rows were missing from the manifest,
web-types and the VS Code data (web-dropzone's satellites lost four inputs). The plugin now reads the
imported module (`.js` → `.ts`, `/index.ts`) and takes its exported `const` array. A package import still warns.

### `deepActiveElement()` and `escapeHtml()` on the main index

```js
import { deepActiveElement, escapeHtml } from '@keenmate/web-components-core';
```

`deepActiveElement()` returns the focused element, looking inside open shadow roots (`document.activeElement` stops at
the outermost host). `escapeHtml()` escapes `& < > " '` for element content and quoted attributes and takes any
value: `null` / `undefined` → `''`, anything else through `String()` (a badge count). `/search` still exports the same function.

## Fixes

- **A focus-opened popover no longer closes in WebKit.** WebKit scrolls the focused input into view a
  frame after `focus` opened the layer, and the shared scroll rule closed it at once. When the focused
  element belongs to the layer and isn't fully visible yet, the first two frames after opening (50 ms
  without `requestAnimationFrame`) move the starting point instead of closing; every other open has no
  such window, so a scroll right after opening still closes it.
- **A Tab-opened dropdown no longer closes in Firefox.** Firefox follows its scroll-into-view of the
  focused field with a 1px correction 10–25 ms later; the rule counted any move of ≥ 1px. It now needs
  ≥ 3px from where the layer opened (small moves still add up).
- **A context menu closes when the component's own scroller moves what was clicked.** A point menu
  (`openMenu({ at: { x, y } })`) watched only scrollers around its host, so scrolling web-grid's or
  web-treeview's body left it open at stale coordinates. It now belongs to the element under the point
  inside the host; a point without finite coordinates no longer throws.

## Examples and docs

- **SPEC §6.4 — disabled / readonly:** every data-input component has the pair `isDisabled` +
  `isReadonly` (`toBool('presence')`, reflected), with native meaning. Disabled means no interaction, not
  focusable, not submitted. Readonly means the data can't change but the component stays focusable,
  navigable and copyable, and its value is submitted. Calls from code still work under both. Show / launch
  components have neither.
- **`docs/usage.md`:** the canonical `createCustomStyles()` snippet refreshes once per build, and a new
  "Typing the properties" section shows the one-line config-interface merge (rulebook C-CA-16).
