# Web Components Core 1.0.0-rc19 — Release Notes

**Released:** 2026-11-08 · **Pre-release** (`npm install @keenmate/web-components-core@rc`)

rc19 makes `createPopover()` able to carry a component's own big dropdown: the panel can stay
mounted, open without being positioned (a fullscreen sheet), re-anchor while open and close on a
scroll like a native select. web-multiselect's dropdown runs on it from its next rc. The overlay
tree now decides an outside click when the click **ends**, so a page button that drives an
overlay through its API no longer closes and reopens it. Also: page-wide custom CSS per component
type, `theme-source="closest"` following a section themed later, and three renames.

**Upgrading needs a small action from component authors** (three renames; the new outside-click
timing and `onClose(reason)` for programmatic closes are worth a test run). Pages using components
need nothing.

The exhaustive, per-change list is in [`CHANGELOG.md`](https://github.com/KeenMate/web-components-core/blob/v1.0.0-rc19/CHANGELOG.md#100-rc19---2026-11-08);
this document is the upgrade guide and the highlights.

## Breaking changes

### Renames

Two types (the rulebook's closed TypeScript suffix set forbids `Type`, C-NC-11) and one option
(a three-way mode, not a flag, C-NC-3). No aliases.

| Before | After | Where |
|---|---|---|
| `PointerType` | `PointerAccuracy` | main index (`EnvironmentSnapshot.pointer` keeps its name) |
| `ExtractedType` | `ExtractedTypeAnnotation` | `/cem` |
| `lockPlacement: boolean \| 'freeze'` | `lockPlacement: PlacementLock` (`'initial' \| 'freeze' \| false`); `true` → `'initial'` | `anchor()`, `createPopover()` |

### `createPopover()` `onClose(reason)` fires for every close

It reported only the overlay tree's closes (Escape, outside click, parent). `close()` and
`destroy()` in code now report `'api'`, and the new scroll / resize rules report `'scroll'` /
`'resize'`. A handler that cleans up on close now sees the programmatic close too.

### Outside clicks are decided when the click ends

The press records the overlays it started outside of; once the click has run the page's own
handlers, those it also ended outside of close (like the browser's popover light dismiss). An
overlay (re)activated during the click stays open, and an API method can call the new
**`claimCurrentClick()`** (`OverlayHandle`, `PopoverHandle`). A keyboard "click" and a cancelled
touch close nothing. `/menu` keeps its own `pointerdown` dismissal. With mixed core copies on one
page, an older copy's router leaves the new entries alone.

## New features

### `createPopover()` for a component's own panel

| Option / method | What it does |
|---|---|
| `shouldKeepMounted` | leaves a component-owned panel where it is; open / close toggle `visibleClass` (or `hidden`) |
| `isAnchored` / `setAnchored(bool)` | open or switch the panel without positioning it (a fullscreen / modal presentation); un-anchoring puts back its own `position` / `left` / `top` |
| `reanchor()` | re-reads the reference and forgets a frozen placement while open (async results) |
| `reference` as a function | asked at each open / re-anchor |
| `container: ShadowRoot` | the panel keeps the component's styles |
| `visibleClass` | added on open, removed on close; the panel is `visibility: hidden` until its first position |
| `shouldCloseOnScroll` | a scroll of the page or a scroller around the reference (also in shadow roots), once the reference moved since open; never a scroll inside the panel or of an unrelated scroller |
| `shouldCloseOnResize` | closes on a window resize |
| `shouldCloseOn*` as a function | asked each time; return `false` to stay open |
| `getInsideElements` | more elements a press on doesn't count as outside |
| `returnFocusTo` | focus target after Escape (`null` = none) |
| `inheritThemeFrom: false` | copies no theme |
| types | `PopoverCloseReason`, `PopoverCloseRule` |

```ts
const popover = createPopover({
  reference: () => host,
  panel,
  container: shadowRoot,
  shouldKeepMounted: true,
  visibleClass: 'ms__dropdown--visible',
  isAnchored: false,                       // render first, then setAnchored(true)
  shouldCloseOnOutsideClick: true,
  getInsideElements: () => [host, hint],
  shouldCloseOnScroll: () => mode === 'floating',
  onClose: (reason) => emit('close', { reason }),
});
```

The overlay tree takes the same: `registerOverlay()` options `shouldCloseOn*` as functions and
`getInsideElements`, `activate({ returnFocusTo })`.

### `anchor()` `fallbackPlacements`

The placements flip tries, in order (grid's dropdown, datepicker, toolbar and tooltip each pass a
list to floating-ui directly today).

### Page-wide custom CSS per component type

```js
window.components['web-daterangepicker'].customStyles = "@import url('/css/drp-days.css');";
window.components['web-daterangepicker'].getCustomStylesCallback = (ctx) => /* per instance */ '';
```

Styles every instance on the page (one file, fetched once), in its own `<style>` before the
instance's `customStyles` / `getCustomStylesCallback`, so an instance still overrides it;
assigning it updates every live instance. The callback wins over `customStyles`. Components adopt
it through **`createCustomStyles(host, root, { getContext, getInstanceStyles, … })`** →
`{ refresh, destroy }`. `StyleSlot` gains a read-only `element`.

## Visible changes without a migration

- `anchor().destroy()` puts back the `width` / `min-width` / `max-width` / `max-height` it wrote
  (`matchWidth`, `maxWidth`, `maxHeight`); a reused panel no longer keeps a stale cap. `left` /
  `top` stay.
- `toCssLength()` takes a number on the property path too: `el.maxWidth = 120` stores `"120px"`,
  like the attribute (it was refused).

## Fixes

- **`theme-source="closest"` follows a section themed later.** The nearest themed ancestor was
  picked once, at connect; core now re-resolves whenever an ancestor gains or loses a theme signal
  (`class` / `data-theme` / `data-bs-theme`).
- **`/menu` toggled-item colour** falls back to `--base-primary-color` (it read the renamed
  `--base-accent-color`).
- **CEM:** the `motion` description states the closest-wins order.
