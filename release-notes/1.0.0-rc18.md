# Web Components Core 1.0.0-rc18 — Release Notes

**Released:** 2026-11-04 · **Pre-release** (`npm install @keenmate/web-components-core@rc`)

rc18 is the result of a full code review of core (2026-11-03). It acts on the review's ~135 findings,
many of them in the places where **several components share one page** (each component bundles
its own copy of core), and it lands **every API change the review called for in this one
release**, so each component migrates once. It also adds nested overlays with Escape /
outside-click routing, a CSS-length converter, a safe highlight API and closest-wins logging.

**Upgrading needs action from component authors** (renames, the loader class, logging
semantics; see the checklist). Pages using components need nothing, unless they style a
component's `-loader` class or use the logging switches.

The exhaustive, per-change list is in [`CHANGELOG.md`](https://github.com/KeenMate/web-components-core/blob/v1.0.0-rc18/CHANGELOG.md#100-rc18---2026-11-04);
this document is the upgrade guide and the highlights.

## Upgrade checklist

**Component authors**

- [ ] Rename the notification options to `on*` and the render hooks to `*Callback`
      ([table](#notification-hooks-are-on)).
- [ ] `menuDivider()` → `createMenuDivider()`; `openMenu({ loadingText })` → `openMenu({ labels: { loading } })`.
- [ ] `toEnum({ shouldNullOnInvalid })` → `toEnum({ isNullable })`.
- [ ] Loader CSS: `.x-loader` → `.x__loader` ([details](#the-default-loader-class-is-bem)).
- [ ] Page loader hook: `window.components.renderLoaderCallback` → `renderLoadingCallback`.
- [ ] `wrapRanges()` now escapes: pass trusted HTML labels through `highlightHtml()` instead
      ([details](#wrapranges-escapes-by-default)).
- [ ] Logging: an element's level now replaces its type's, and `el.disableLogging()` silences
      ([details](#logging-the-closest-level-wins)). Check tests that spy on `console.debug` for
      instance lines (they go to `console.log`).
- [ ] Run your tests: number attributes are parsed strictly, `el.x = undefined` resets, `toText`
      accepts `''`, `emit()` no longer mutates the detail you pass ([details](#behaviour-changes)).
- [ ] Regenerate the CEM manifest (it now lists `BlissElement`'s own API and reads more table shapes).
- [ ] Optional: popovers can drop their own Escape / outside-click code
      (`createPopover({ shouldCloseOnEscape, shouldCloseOnOutsideClick })`).

**Pages using components**

- [ ] If your CSS targets a component's `<prefix>-loader` class, use `<prefix>__loader` once that
      component ships on this core.
- [ ] If you use the logging switches: the closest level now wins
      ([details](#logging-the-closest-level-wins)).

**pure-css**

- [ ] Port the `anchor()` / containing-block changes and join the shared scroll lock (entries
      marked *pure-css port affected* in the CHANGELOG).

## Breaking changes

### Notification hooks are `on*`

`*Callback` now always means "you decide" (a return value matters); a hook that is only told
something is `on*`.

| Before | After | Where |
|---|---|---|
| `closeCallback(reason)` | `onClose(reason)` | `openMenu` |
| `placedCallback(placement)` | `onPlaced(placement)` | `anchor`, `createPopover` |
| `computedCallback({ x, y, placement })` | `onComputed(…)` | `anchor` |
| `driftCallback(report)` | `onDrift(report)` | `anchor` |
| `objectTermCallback(term)` | `onObjectTerm(term)` | `prepareSearchTerm` |
| `renderItem` / `renderMenu` / `prepareItem` | `renderItemCallback` / `renderMenuCallback` / `prepareItemCallback` | `openMenu` |

Also renamed: `menuDivider()` → **`createMenuDivider()`** (the `create` factory prefix);
`openMenu({ loadingText })` → **`openMenu({ labels: { loading } })`** (new `MenuLabels` type);
`toEnum({ shouldNullOnInvalid })` → **`toEnum({ isNullable })`**; the page-wide loader hook
`window.components.renderLoaderCallback` → **`renderLoadingCallback`** (the instance hook's name).
No compatibility aliases.

### The default loader class is BEM

`renderLoader()` draws `<span class="<prefix>__loader">` (was `<prefix>-loader`), so the
rulebook's naming checks pass. Rename the selector; the `--<prefix>-loader-*` tokens and the
`<prefix>-loader-spin` keyframes keep their names:

```css
/* rc17 */ .wtv-loader  { … }
/* rc18 */ .wtv__loader { … }
```

A published component keeps its spinner until it is rebuilt on rc18 (each bundles its own core).

### Logging: the closest level wins

```
element (el.enableLogging) → component type (window.components[tag].logging) → page (window.components.logging) → warn
```

Nothing is set by default, so a fresh page prints warnings and errors as before. What changed:

| Call | rc17 | rc18 |
|---|---|---|
| `el.enableLogging('error')` | added to the type's level | this element: errors only |
| `el.disableLogging()` | cleared the element's level | this element: silent |
| `el.resetLogging()` | — | clears the element's level (follow type / page) |
| page call after a type call | the last call won | the type's own level wins |

New `resetLogging()` on the type controls, bundles and `window.components.logging`;
`setCategoryLevel(category, null)` clears one category. An invalid level warns and changes
nothing. Instance `debug` / `trace` lines go through `console.log` (Chrome hides `console.debug`).

### `wrapRanges()` escapes by default

`wrapRanges(text, ranges)` used to insert the label raw (an XSS path with user-supplied labels). It
escapes now; for a label that is already trusted HTML, use the new
`highlightHtml(html, term, opts)`, which marks text runs only. `escape: (s) => s` restores the old
behaviour.

### Page-wide motion goes on `<html>`

`window.components.motion` is written once on `<html data-motion>` instead of on every host, so a
nearer `<section data-motion>` wins. A host gets `data-motion` only for its own `motion`.

### Behaviour changes

- **Strict numbers:** `toInt` rejects `"12px"`, `"1.9"`, `"1e3"`, `"0x10"`, `"1,5"` (they became
  12, 1, 1, 0, 1); `toFloat` rejects `"1.5em"`, `"Infinity"`. A rejected attribute warns and keeps
  the previous value.
- **`el.x = undefined` resets** the input to its default, like removing the attribute.
- **`toText`:** `el.label = ''` clears like `label=""` (it was rejected); `shouldTrim` trims
  assigned strings too. Custom converters get an optional `normalize(value)`.
- **`toEnum`** matches attributes case-insensitively and trims them.
- **`toList`:** an item holding the separator round-trips through a JSON-array attribute; `[]`
  reflects as `"[]"`; an empty item in the separated form (`"a,b,"`) is invalid.
- **`emit()`** shallow-copies a plain-object detail instead of attaching the context to your
  object; the twin and the event still share one object.
- **Search folding:** `ß` → `ss`, `İ` → `i`, ligatures / full-width / NBSP fold; combining marks
  are stripped only after Latin, Greek and Cyrillic letters.
- **CEM:** `index.ts` is no longer excluded (that's where `registerComponent()` is called);
  manifests list `BlissElement`'s own API.

## New features

| Feature | API |
|---|---|
| Nested overlays | a menu inside a dropdown, a dropdown inside a modal: the parent stays open. `registerOverlay(onDismiss, group, { getElement })`, `activate({ trigger })`; closing an overlay closes the ones opened inside it |
| Escape / outside-click routing | `registerOverlay(…, { shouldCloseOnEscape, shouldCloseOnOutsideClick })`: Escape closes the deepest overlay and returns focus; `createPopover()` takes the same options plus `overlayGroup` and `onClose(reason)` |
| Panels in a modal `<dialog>` | the default container is the nearest open modal dialog / popover; `findOverlayContainer(trigger)` |
| CSS lengths | `toCssLength({ default?, allowNegative?, keywords? })`: `"12px"`, `"2rem"`, `calc(…)`; a bare number means px |
| Byte units | `toBytes()` takes `k` / `m` / `g` / `t` and `KiB` / `MiB` / … |
| Safe highlighting | `/search`: `escapeHtml()`, `highlightHtml()` |
| Logging | `resetLogging()`, `isLogLevel()`, `toLogLevelNumber()`, `getCoreLogging()`, `Logger.resetLevel()` |
| Actions | `ResolvedActionItem.isToggle`, `isActionBusy(item, host?)` |
| Testing | `/testing`: `resetPageState()`, `captureConsole()`, `waitForEvent()` |
| Packaging | `./package.json` export, `engines`, `CemPackageDoc` / `CORE_DECLARED_API` from `/cem` |

The README gained an **API index** of every runtime export.

## Visible changes without a migration

- Several components on one page now share one scroll lock, one breakpoint table, one
  `dismissAllOverlays()`, one instance registry and one logging switch (each used to have its own
  per copy of core).
- `lockBodyScroll()` pins `<body>` (iOS Safari ignored `overflow: hidden`) and pads it by the
  scrollbar width, so the page doesn't shift sideways.
- A soft keyboard no longer turns a landscape tablet into `mobile`; `sizeChanged()` reports the
  layout size (not a `scale()`-animated box); breakpoint tokens applied late during load are
  picked up.
- New table-check warnings: an unknown `on` value, a `configKey` hiding a `BlissElement` member,
  `getLiveValue` on an `on: 'none'` row, two events sharing one `on<Name>` property.
- A component loaded twice keeps its first registration (and warns).

## Fixes

Highlights; the CHANGELOG has the full list.

- An invalid `motion` attribute first in markup no longer drops every attribute after it.
- A throwing hook or listener no longer leaves an element half-activated, hangs `whenReady()`, or
  silences the other listeners.
- `window.components.logging.setLogLevel('verbose')` no longer breaks every component loaded later.
- Properties assigned before upgrade (`motion`, `themeSource`) are applied; an element inserted
  into a `<fieldset disabled>` is disabled in its first build.
- Menus: the keyboard belongs to the menu only while focus is in it; Tab works in a custom menu;
  RTL submenus; hover intent; two open menus close one Escape at a time.
- Positioning: `createPopover()` forwards every `anchor()` option; tooltips get
  `aria-describedby`, close on Escape and can be hovered; `contain: paint` wrappers are handled;
  `onDrift` reports only real drift.
- `scrollIntoContainer()` never scrolls an `overflow: hidden` wrapper; `%` scroll-padding resolves.
- Regex highlights never split an emoji; a write inside `update()` before `this.flush()` is kept.
