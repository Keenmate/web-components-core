# Web Components Core 1.0.0-rc24 — Release Notes

**Released:** 2026-11-15 · **Pre-release** (`npm install @keenmate/web-components-core@rc`)

rc24 also carries 1.0.0-rc23, which was never published: there is no rc23 on npm, upgrade from rc22
straight to rc24.

rc24 finishes the phone sheets. Every component's sheet gets one header bar from core
(`SHEET_CHROME_CSS` + `createSheetHeader()`) and one phone Back gesture (`claimBackEntry()`); `/menu`
gains a side drawer, a per-device presentation map and open / close animations; closing a sheet no
longer scrolls the page to the top. For animations there is now one rule — `motion` is the only
switch — and one helper to animate something out, `animateOut()`. **Upgrading needs no code change**
unless you style the menu sheet with the two removed variables or read the sheet's `history.state`.

The exhaustive list is in [`CHANGELOG.md`](https://github.com/KeenMate/web-components-core/blob/v1.0.0-rc24/CHANGELOG.md#100-rc24---2026-11-15).

## Upgrade checklist

**Component authors**

- [ ] Bump to `^1.0.0-rc24`.
- [ ] A phone sheet / modal that closes on the Back gesture: replace your own `history.pushState()` +
      `popstate` listener with `claimBackEntry()` ([details](#claimbackentry-the-phone-back-gesture)).
      Rulebook C-RO-15 flags the old pattern.
- [ ] A phone sheet with its own header / title / close button: build it with `createSheetHeader()` +
      `SHEET_CHROME_CSS` and map your `--<prefix>-sheet-*` variables onto `--_km-sheet-*`
      ([details](#one-sheet-header-sheet_chrome_css--createsheetheader)). Rulebook C-RO-17.
- [ ] A component with a menu: spread `...menuPresentationInputs()` into `static inputs` and pass
      `menuPresentationOptions(this.config)` to `openMenu()` ([details](#menu-drawer-presentation-map-animations)).
- [ ] Something that animates out: use `animateOut()` instead of your own `animationend` listener +
      timeout ([details](#animateout-the-one-way-to-animate-something-out)). Rulebook C-CA-18.
- [ ] No `is…AnimationEnabled` inputs: `motion` is the only switch; one animation is turned off with
      its own duration token ([details](#motion-one-switch)). Rulebook C-NC-15.
- [ ] Tests that read the sheet's history entry: `history.state` is now `{ kmBackEntry: true }`
      (the menu's was `{ kmMenuSheet: true }`).

**Pages**

- [ ] Menu sheet styling: `--km-menu-sheet-header-padding` → `--km-sheet-header-padding-block` /
      `-inline`; `--km-menu-sheet-title-font-weight` → `--km-sheet-title-font-weight`.
- [ ] Something stacked between 9001 and 10000 that must stay above an open menu: menus now default
      to z-index 9001 (`--km-menu-z-index` overrides).

## Behaviour changes

### The menu sheet looks like every other sheet

The `/menu` phone sheet header is the shared sheet chrome: the close button is the round masked ✕
(was a text ✕), the title 18px, the top corners 8px (`--base-border-radius-lg`, was 12px), and the
sheet hides keyboard-shortcut hints (the keys still work with a keyboard). Its sizes read the
base-css-variables scale; without base-css-variables the pixels are unchanged except the corners.

### Menus stack at 9001

`/menu` defaults to `calc(var(--base-z-tooltip, 9000) + 1)` — the tier the components' own phone
sheets use — instead of `10000`.

### One history entry name

The sheet's history entry is `{ kmBackEntry: true }` (was `{ kmMenuSheet: true }`), shared by every
component that uses `claimBackEntry()`. Only code that inspects `history.state` notices.

## New features

### `claimBackEntry()`: the phone Back gesture

```ts
import { claimBackEntry, lockBodyScroll, observeKeyboardInset } from '@keenmate/web-components-core';

// on open (full-screen / modal tier)
const unlock = lockBodyScroll();
const unobserve = observeKeyboardInset(panel);
const releaseBack = claimBackEntry(() => this.close('back'));   // phone Back closes it

// on every close (✕, Escape, a pick, Back — releasing twice is a no-op)
releaseBack();
unobserve();
unlock();
```

- One history entry (same URL) for the whole page while a sheet is open. Back runs the newest claim's
  `onBack`; claiming again from inside `onBack` re-arms the entry (one submenu level up, the sheet stays).
- A release gives the entry back with `history.back()` one task later, so a sheet that opens right after
  takes it over instead of racing a `back()` against a new `pushState()`.
- The page keeps its scroll position (see [Fixes](#fixes)).
- Page-wide state, shared by every copy of core on the page. Was `/menu`'s private helper;
  web-grid, web-multiselect and web-daterangepicker each had their own copy and now use this one.

### One sheet header: `SHEET_CHROME_CSS` + `createSheetHeader()`

A **sheet** is a panel that covers the page on a phone — a bottom sheet, a side drawer, a full-screen
picker. `/menu`, web-grid, web-multiselect, web-daterangepicker and web-dropzone each drew its top bar
on its own; now there is one:

```ts
import { createSheetHeader, SHEET_CHROME_CSS } from '@keenmate/web-components-core';

const { header, close } = createSheetHeader({
  title: 'Pick a date',
  closeLabel: this.labels.close,
  onClose: () => this.close('close-button'),
});
sheet.prepend(header);   // adopt SHEET_CHROME_CSS into the root the sheet lives in
```

- `.km-sheet-header` / `.km-sheet-title` / `.km-sheet-close`: a round 44px chip with the
  `--base-icon-close` mask whose tap area reaches the sheet's corner.
- Themed with `--km-sheet-*` page-wide. A component maps its own `--<prefix>-sheet-*` on `:host`
  (`--_km-sheet-close-size: var(--xx-sheet-close-size);`, no fallback) with the 19 suffixes:
  `header-gap`, `header-padding-block`, `header-padding-inline`, `header-min-height`, `header-bg`,
  `header-border`, `title-color`, `title-font-size`, `title-font-weight`, `close-size`,
  `close-icon-size`, `close-icon`, `close-color`, `close-bg`, `close-bg-hover`, `close-border`,
  `close-border-radius`, `close-edge-nudge`, `close-focus-color`.

### `/menu`: drawer, presentation map, animations

- `presentation: 'drawer'` + `side: 'start' | 'end'`: the phone sheet as a full-height side panel
  (`--km-menu-drawer-width` / `-shadow` / `-border-radius`).
- `presentationMap` (default `DEFAULT_MENU_PRESENTATION_MAP`): what `'auto'` picks per device class,
  e.g. `{ tablet: 'drawer' }`.
- An open `'auto'` menu follows a device-class change: sheet ⇄ drawer in place; to / from floating it
  closes with the new reason `'presentation'`.
- `menuPresentationInputs()` / `menuPresentationOptions(config)`: the standard `menu-presentation` /
  `menu-side` inputs for every menu host, and the matching `openMenu()` options. The CEM generator
  reads the spread, so they appear in `custom-elements.json`.

  ```ts
  static inputs = [...menuPresentationInputs(), /* your rows */];
  openMenu(entries, ctx, { ...menuPresentationOptions(this.config), title: 'Row' });
  ```
- The sheet and drawer slide in and out over a fading backdrop, timed by the motion tokens
  (`--km-menu-sheet-duration` → `--base-duration-medium`); closing plays out before the sheet leaves
  the DOM.

### `animateOut()`: the one way to animate something out

Appearing needs no JavaScript — a `@keyframes` plays when the element is inserted. Disappearing has to
wait for the closing animation before the element is removed or collapsed:

```ts
import { animateOut } from '@keenmate/web-components-core';

const closing = animateOut([panel, backdrop], {
  className: (el) => (el === backdrop ? 'xx__backdrop--closing' : 'xx__panel--closing'),
  onDone: () => { panel.remove(); backdrop.remove(); },
});
// reopened mid-close:
closing.cancel();
```

- Adds the closing class (+ `inert`), waits for each element's own `animationend`, then runs
  `onDone`. A timeout (the longest duration + 50ms) covers a hidden tab or `display: none`.
- Nothing animates (`motion="none"`, a `0s` token, OS reduced motion) → `onDone` runs synchronously.
- `shouldSetHeightVar: true` writes `--km-exit-height` so a row can shrink in the flow
  (`from { height: var(--km-exit-height) } to { height: 0 }`).
- `readAnimationMs(el)` reads what CSS resolved: the longest delay + duration of the element's
  animations, `0` for none.

### Motion: one switch

- `motion` covers decorative animations only — panels sliding, rows expanding, fades, a countdown bar.
  Timers (a feedback that closes after 3s) and activity indicators (a loader) keep running.
- `motion` (element, a section's `data-motion`, `window.components.motion`) is the only switch; there
  are no per-feature `is…AnimationEnabled` inputs.
- One animation is turned off by its own token: `--<prefix>-<what>-animation-duration: 0s`. Its
  default points at a speed token (`var(--<prefix>-transition-normal)` → `--base-duration-*`), so
  `motion` and OS reduced motion still apply to it.

## Fixes

- **Closing a phone sheet no longer scrolls the page to the top.** A sheet locks page scroll first
  (`lockBodyScroll()` pins `<body>`, so the window's scroll is 0) and then pushes its Back entry, so the
  browser recorded 0 for the page's entry and restored it on close, after the scroll lock had put the
  page back. While an entry is held the page's entry now uses `history.scrollRestoration = 'manual'`,
  and gets its own mode back one task after it is current again.
- **A follow-cursor tooltip scrolls with its trigger.** `createTooltip({ shouldFollowCursor })` kept the
  cursor point on screen, so a card tapped on a phone (it keeps focus) left its tooltip floating over
  the page after the card scrolled away. The point is now kept relative to the trigger.
- `observeEnvironment()` / `observeViewport()`: the last unsubscribe no longer removes window /
  document listeners that were never added (no `matchMedia`, e.g. jsdom).
