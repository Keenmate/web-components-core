# Web Components Core 1.0.0-rc16 — Release Notes

**Released:** 2026-11-02 · **Pre-release** (`npm install @keenmate/web-components-core@rc`)

rc16 adds **container scrolling**, `scrollIntoContainer()` and `findScrollContainer()`: a component brings an inner element into
view by scrolling the one container around it, never the page. It also makes **boolean inputs
explicit**: `toBool()` now requires its mode, and the input-table check warns about a row `default`
that can never apply.

**Upgrading needs a small action from component authors:** every `toBool()` call must name its mode.
No KeenMate component used the bare form, so the published components are unaffected. Pages that only
*use* components need nothing.

The exhaustive, per-change list is in [`CHANGELOG.md`](https://github.com/KeenMate/web-components-core/blob/v1.0.0-rc16/CHANGELOG.md#100-rc16---2026-11-02);
this document is the upgrade guide and the highlights.

## Breaking changes

### `toBool` requires its mode

`toBool()` with no argument used to mean `'presence'`: any attribute value, `x="false"` included, is
`true`. Frameworks that render `x={false}` as `x="false"` turned such a flag *on*. The mode is now a
required argument (type `BoolMode`, exported):

| Mode | Missing attribute | `x="false"` | Use for |
|---|---|---|---|
| `'default-false'` | `false` | `false` | the usual opt-in flag |
| `'default-true'` | `true` | `false` | a flag that is on unless switched off |
| `'tristate'` | `null` | `false` | "not set, the engine decides" (null-clear contract) |
| `'presence'` | `false` | **`true`** | `disabled` / `readonly` only — the browser reads those by presence |

```ts
// before
{ configKey: 'isOpen', attribute: 'is-open', converter: toBool() }
// after — pick what you mean
{ configKey: 'isOpen', attribute: 'is-open', converter: toBool('default-false') }
```

## New features

### Container scroll

`Element.scrollIntoView()` scrolls every scrollable ancestor, the page included, so a search jump or
an arrow key made the whole page jump. The new helpers scroll one container:

| Function | Returns |
|---|---|
| `findScrollContainer(el, { stopAt?, axis? })` | the nearest ancestor that actually scrolls, or `null` (only the page scrolls) |
| `scrollIntoContainer(el, { block?, inline?, behavior?, container?, revealContainer?, stopAt?, axis? })` | the container it scrolled, or `null` (page fallback) |

- **Finding the container.** It walks up the tree the browser lays out: out of a shadow root to its host, and
  from slotted content into its slot. A scroller is an element with `overflow: auto | scroll |
  overlay` on the axis and content larger than its box; `overflow: hidden` never counts, and neither
  do `<html>` / `<body>`. `stopAt` ends the search before that element; `axis` is `'y'` (default),
  `'x'` or `'both'`.
- **Scrolling.** `block` / `inline` take `nearest` (default: move only as far as needed),
  `start`, `center`, `end`. `inline` is logical: in a right-to-left container `start` is the right
  edge. The container's `scroll-padding` and the element's `scroll-margin` are honoured, so a sticky
  header is handled in CSS. When nothing needs to move, `scrollTo()` isn't called at all.
- **No container.** The page is the only scroller and gets the same request,
  `el.scrollIntoView({ block, inline, behavior })`: a `center` jump in a component with no scroller of its own
  centres the row in the window.
- **`revealContainer: true`** first brings a container that isn't fully on screen into the viewport.
  This is for jumps to a list further down the page.
- An element inside an iframe is measured against the iframe's own document.

```ts
import { scrollIntoContainer } from '@keenmate/web-components-core';

scrollIntoContainer(row);                                              // keyboard move: nearest, instant
scrollIntoContainer(hit, { block: 'center', behavior: 'smooth', revealContainer: true }); // search jump
scrollIntoContainer(option, { container: this.listEl });               // known scroller, no search
```

Not covered: virtual lists (scroll by index), CSS-scaled containers (the amount is unscaled),
vertical writing modes, and nested scrollers (only the innermost moves unless `revealContainer`).
Deciding *whether* to scroll stays with the component: a component that scrolls on its own exposes
a `beforeScrollCallback` and runs it through `runBeforeCallbackSync`. See **SPEC §12.15**.

### Dead `default` warning

The once-per-class input-table check (the one that flags duplicate keys) now also warns when a row's
`default` can never apply. A converter's answer for a missing attribute wins, and `default` fills in only
for `undefined`, so `toBool('default-false')` with `default: true` starts `false`, and `toText()`
with `default: 'Hello'` starts `''`:

```
invalid input table: "isOpen" declares default true, but its converter resolves a missing attribute
to false — the default never applies. …
```

A `null` answer is exempt: it's the null-clear "unset, the engine decides" marker, where `default`
documents what the engine applies. The check only warns; behaviour doesn't change.

- New console warnings for dead defaults (above). Every KeenMate component was checked against this
