# Web Components Core 1.0.0-rc22 — Release Notes

**Released:** 2026-11-11 · **Pre-release** (`npm install @keenmate/web-components-core@rc`)

rc22 comes from moving web-grid's and web-dropzone's popups onto core: context and column menus become a
bottom sheet on phones, elements a component mounts take the component's custom CSS, and four fixes —
mixed themes on portaled panels, phantom scroll-lock padding on wide phone pages, aliased classes in the
`/cem` plugin, plus two SPEC rules. **Upgrading needs no code change.**

The exhaustive list is in [`CHANGELOG.md`](https://github.com/KeenMate/web-components-core/blob/v1.0.0-rc22/CHANGELOG.md#100-rc22---2026-11-11).

## Behaviour changes

### Menus are a bottom sheet on phones

`openMenu()` defaults to `presentation: 'auto'`, which follows core's phone switch
`resolvePresentation()` — the one web-multiselect and web-grid's cell editors use. On a phone every
component's context / column menu now opens as a full-width bottom sheet instead of a small floating
panel. Tablet and desktop are unchanged. `presentation: 'floating'` keeps the old behaviour on every
device; `'sheet'` forces the sheet.

## New features

### `/menu`: a bottom sheet on phones

- A backdrop, safe areas (`env(safe-area-inset-*)`, `dvh`), rows at least `var(--base-touch-target-min, 44px)`
  tall, page scroll locked while open.
- A header from the new `title` option (also the menu's `aria-label`) and a close button.
- Submenus drill in: the sheet's content is replaced by the submenu, with a Back row.
- The phone Back button goes up one submenu level, or closes the menu at the top (one history entry,
  like web-multiselect).
- A backdrop tap closes it as `'outside-click'` without clicking the page behind; focus returns.
- New `onClose` reasons `'back'` and `'close-button'`; new labels `back` / `close`.
- New variables `--km-menu-backdrop`, `--km-menu-sheet-*`, `--km-menu-back-arrow` (in
  `component-variables.manifest.json`). `cssClass` stays on the menu levels, not the sheet wrapper.

### Custom CSS for managed children: `getOwner`

An element a component mounts and owns (web-dropzone's bulk-mode picker, list and progress) can name its
owner:

```ts
createCustomStyles(this, this.shadowRoot, {
  cssClass: 'dz-custom-styles',
  getContext: () => this.withContext({}),
  getInstanceStyles: () => ({ css: this.config.customStyles, callback: this.config.getCustomStylesCallback }),
  getOwner: () => this.#store?.host ?? null,   // read per refresh; null = no owner layers
});
```

The child then gets four layers, in this order: its own page layer → the owner's page layer → the owner's
instance layer → its own instance layer (slots `<cssClass>--owner-page` and `<cssClass>--owner`). The
owner's CSS is what the owner's own handle last resolved, so the owner's callbacks run once, with the
owner's context. A page write for either tag, or the owner's `refresh()`, refreshes the child; `@import`
hoisting covers the added layers. No owner, a throwing `getOwner` (logged), the host itself, or an owner
destroyed or really removed from the page means no owner layers — today's behaviour.

## Fixes

- **`inheritThemeFrom` — no mixed theme on a portaled panel.** Each theme attribute was copied from its
  own nearest carrier, so a section's `data-theme="dark"` above a component host reached the panel next to
  the host's `data-context-theme="light"`; the panel's per-instance rules won and it rendered dark beside a
  light component. Above the nearest host carrying `data-context-theme`, `data-theme` / `data-bs-theme`
  are no longer copied; the host's own `data-theme` still is. Without such a host the nearest carrier is
  copied as before. Affects `anchor()`, `createPopover()` and `/menu`.
- **`lockBodyScroll()` — no phantom `padding-right` on a phone page wider than the screen.** The scrollbar
  compensation was `innerWidth - documentElement.clientWidth`; on a zoomed-out phone page that is the
  horizontal overflow (651px in web-grid's phone fixture). It now compares the root's `clientWidth` before
  and after pinning: exactly the vertical scrollbar that disappears, 0 with overlay scrollbars / touch.
- **`/cem` — aliased and re-exported classes.**
  `registerComponent('web-grid', _GridElement)` with an aliased import gave "No components found". The
  class argument now resolves through import aliases, default imports and relative re-exports
  (`export { a as b } from`, `export * from`); registrations analyzed before their class module are linked
  in `packageLinkPhase`, so module order no longer matters. An unresolvable registration is a
  `[keenmate-bliss-inputs]` build warning naming the tag and the identifier. Shared row spreads
  (`...SHARED`) follow re-exports the same way.

## Documentation

- **SPEC §6.4 — readonly text surfaces:** focus, select and copy are the minimum; a caret that moves with
  the arrow keys is optional.
- **SPEC §6.4 / §11.4 — store / satellite components:** only a satellite that is itself a data-input
  surface gets `isDisabled` + `isReadonly`; the others follow the bound store. Satellite events are declared
  in the satellite's `static events` and sent through `emit()` (the `on*` twin and the manifest entry come
  free); their `controller` is the bound store's. Satellites take their owner's custom CSS (§12.8).
- **`docs/usage.md`:** the `getOwner` adoption and the menu sheet options (`presentation`, `title`).
