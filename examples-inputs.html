Reactive inputs

Core's headline: every public input of a BlissElement — attribute, property or callback — is ONE row of a static inputs table. Its converter parses the attribute and validates the property, so both entry points share one pipeline: parse/validate → stage → coalesce → reinit() or update(partial). See SPEC §4–§6, §12.7 and docs/reactivity-and-batching.md.

IN01 · One input table, two entry points

<core-demo-inputs> declares six inputs, one per converter type. Write each one as an attribute (setAttribute) or as a property (el.x = …) — both land in the same validated value, and both re-render the chip. Rows with shouldReflect: true write a property assignment back to the attribute (limit doesn't reflect — compare). Removing an attribute resets the input to its default (absent == default). formatLabelCallback is a property-only callback input (toFunction(); null clears it).

configKeyattributeconverterwriteel[configKey]getAttribute()
 
import { BlissElement, define, toBool, toEnum, toFunction, toInt, toList, toText } from '@keenmate/web-components-core';

class CoreDemoInputs extends BlissElement {
  static inputs = [
    { configKey: 'label',     attribute: 'label',   converter: toText({ default: 'Inbox' }),                  shouldReflect: true },
    { configKey: 'count',     attribute: 'count',   converter: toInt({ min: 0, max: 10, default: 3 }),       shouldReflect: true },
    { configKey: 'limit',     attribute: 'limit',   converter: toInt({ min: 1, max: 100, default: 50 }) },   // not reflected
    { configKey: 'isCompact', attribute: 'compact', converter: toBool('presence'),                           shouldReflect: true },
    { configKey: 'tone',      attribute: 'tone',    converter: toEnum(['info', 'success', 'warning'], { default: 'info' }), shouldReflect: true },
    { configKey: 'tags',      attribute: 'tags',    converter: toList({ default: ['mail', 'work'] }),        shouldReflect: true },
    { configKey: 'formatLabelCallback', converter: toFunction(), default: null },               // property-only
  ];
  reinit() { this.#render(); }          // reads the merged this.config
  update() { this.#render(); }          // on defaults to 'update'
}
define('core-demo-inputs', CoreDemoInputs);

el.setAttribute('count', '7');   // fromAttribute('7') → 7
el.count = 7;                    // validate(7) → ok → reflected: count="7"
el.removeAttribute('count');     // → default 3

IN02 · Invalid values: warn, keep the previous value

One rule on both paths: a value the converter rejects warns and keeps the previous value (the default before any valid one). On the attribute path the converter flags a bad string through fromAttribute's reportInvalid argument; a reflected input then writes its current value back, so the DOM shows what the element really uses — a non-reflected one leaves your markup alone. Warnings go through the element's logger ([CORE:ELEMENT] tag#id, default level warn); the log below captures them from the console. 

// A custom converter reports a bad attribute string the same way the to* factories do:
const toPercent = toCustom((raw, reportInvalid) => {
  if (raw === null) return 100;
  const n = Number(raw);
  if (!Number.isFinite(n) || n < 0 || n > 100) reportInvalid?.('expected 0..100');
  return n;                     // ignored when reported invalid — the previous value stays
}, { validate: (v) => typeof v === 'number' && v >= 0 && v <= 100, toAttribute: String });

el.setAttribute('count', 'abc'); // warn · count stays 5 · reflected → attribute rewritten to "5"
el.count = 99;                   // warn · count stays 5 (max: 10)

IN03 · update(partial) vs reinit()

Reactivity is declared per row with on. 'update' inputs reach update(partial) with just the changed keys; 'reinit' inputs trigger a full reinit() that rebuilds from the merged this.config (watch the build # stamp); 'none' inputs are stored only. A mixed batch runs reinit() alone — the rebuild absorbs the update keys, so no partial is sent.

reinit() × 0 update() × 0 
static inputs = [
  { configKey: 'caption',  attribute: 'caption',   converter: toText({ default: 'Report' }), on: 'update' },
  { configKey: 'accent',   attribute: 'accent',    converter: toEnum(['blue', 'green', 'red'], { default: 'blue' }), on: 'update' },
  { configKey: 'layout',   attribute: 'layout',    converter: toEnum(['list', 'grid'], { default: 'list' }), on: 'reinit' },
  { configKey: 'pageSize', attribute: 'page-size', converter: toInt({ min: 1, max: 12, default: 4 }), on: 'reinit' },
  { configKey: 'note',     attribute: 'note',      converter: toText(), on: 'none' },
];
reinit()        { /* rebuild everything from this.config */ }
update(partial) { /* patch only partial's keys — e.g. { caption: 'Quarterly' } */ }

el.setAttributes({ caption: 'Mixed', layout: 'grid' });  // → reinit() only, no update partial

IN04 · Batching, whenSettled() and flush()

Loose property assignments in the same synchronous block coalesce on a microtask into one flush — nothing has run right after the writes; await el.whenSettled() is the deterministic read-after-write signal. Assignments split across ticks are one flush each. setAttributes({…}) and batch(fn) make the batch explicit and flush synchronously. An imperative method that reads live state calls this.flush() first, so el.x = …; el.method() works without an await. Configuring a detached element and appending it builds once. 

el.caption = 'A'; el.accent = 'green'; el.caption = 'B';
// nothing has run yet — one microtask flush is queued
await el.whenSettled();                 // → ONE update({ caption: 'B', accent: 'green' })

el.setAttributes({ caption: 'C', 'page-size': 6 });   // configKey or attribute name; flushed now
el.batch(() => { el.caption = 'D'; el.accent = 'red'; });  // one flush, synchronous

// Inside the component — imperative methods flush first:
readRendered() { this.flush(); return { ...this.#rendered }; }
el.pageSize = 8; el.readRendered().pageSize;          // 8, no await needed

// Pay for the build once: configure detached, then append
const fresh = document.createElement('core-demo-reactivity');
fresh.setAttributes({ layout: 'grid', pageSize: 8 });
document.body.append(fresh);            // ONE reinit() with the full config

IN05 · Presets (getBatchValuesCallback) & live getters (getLiveValue)

A row's getBatchValuesCallback(value, config) returns other inputs to set in the same batch — so mode sets editTrigger + hasGridLines and the component sees ONE update with all three keys. Each returned value goes through its own converter and reflects. An input set explicitly in the same batch wins over the preset. A row's getLiveValue(el) makes the property getter return live component state: add rows inside the component and el.items reports them, while this.config.items keeps the assigned array. Right after an assignment (still staged) the getter returns what you just assigned. 

static inputs = [
  { configKey: 'mode', attribute: 'mode', converter: toEnum(['simple', 'excel', 'custom'], { default: 'simple' }),
    shouldReflect: true,
    getBatchValuesCallback: (mode) => ({
      simple: { editTrigger: 'click',    hasGridLines: false },
      excel:  { editTrigger: 'dblclick', hasGridLines: true },
    })[mode] ?? null },                                   // null / {} → set nothing else
  { configKey: 'editTrigger',  attribute: 'edit-trigger', converter: toEnum(['click', 'dblclick', 'none']), shouldReflect: true },
  { configKey: 'hasGridLines', attribute: 'grid-lines',   converter: toBool('presence'), shouldReflect: true },
  { configKey: 'items', converter: toObjectArray(), default: [], on: 'reinit',
    getLiveValue: (el) => el.liveRows },                 // undefined → falls back to the stored value
];

el.mode = 'excel';                  // → ONE update({ mode, editTrigger: 'dblclick', hasGridLines: true })
el.setAttributes({ mode: 'excel', editTrigger: 'none' });   // explicit editTrigger wins

IN06 · API summary

APIWhat it does
static inputs: InputDef[]The opt-in input table. Each row: configKey, optional kebab attribute, converter, default, on, shouldReflect, getBatchValuesCallback, getLiveValue, doc-only description / type / deprecated. Sanity-checked once per class (warns on duplicates, reflect without attribute / toAttribute).
Converter<V>fromAttribute(raw, el, attr, reportInvalid) (attribute path), validate(value) (property path), optional toAttribute(value) (reflection).
toText · toInt · toFloat · toBool · toEnum · toList · toBytesScalar / list converters; one set of options drives both paths.
toValue · toObject · toObjectArray · toFunction · toCustomRich values (JSON on the attribute path), callbacks (property-only, null clears), bespoke parsers.
on: 'update' | 'reinit' | 'none'What a change triggers (default 'update'). A batch with any reinit key calls reinit() only.
protected reinit()Full rebuild from this.config: first connect + any batch changing an on: 'reinit' input.
protected update(partial)In-place patch with just the changed on: 'update' keys (no reinit key in the batch).
protected configThe validated, effective config (defaults + attributes + properties + responsive overrides).
setAttributes(values)Apply many inputs (by configKey or attribute name) as one synchronous flush.
batch(fn)Run fn; coalesce its property writes into one synchronous flush.
whenSettled(): Promise<void>Resolves after the pending flush ran (immediately when nothing is pending; on next connect while detached).
flush()Apply pending writes now — call it at the top of imperative methods.
getBatchValuesCallback(value, config)Row field: other inputs to set in the same batch; explicit writes in that batch win; one level only.
getLiveValue(el)Row field: the getter returns live state after the first build (not while the write is staged); undefined → stored value. Setter and this.config unchanged.
