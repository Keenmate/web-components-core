NC01 · Two absent-sentinels, never conflated

The partial an engine receives carries two distinct kinds of “absent”:

The rule
undefined = not in this batch — the key didn't change, leave the engine's current value alone (this is what the if (updates.x !== undefined) guard skips).
null = explicitly cleared — a real value, produced when a nullable input is emptied (removeAttribute or el.prop = null). It is the input's declared unset state, so a set→clear round-trip returns the field to how it was born.

NC02 · collectEngineConfig preserves null

The pure assembler, driven directly (no component). Set a value, then clear it, and watch the assembled config: the key stays present with null — it is not dropped. That is what makes the clear work: the engine's if (updates.x !== undefined) guard skips a key that is missing, so a dropped key would leave the old value in place.

NC04 · API summary

            
// Component side — assemble the config to hand your engine:
protected override update(partial = {}) {
  const cfg = this.getEngineConfig(NON_ENGINE_KEYS); // shallow copy, nulls PRESERVED
  Object.assign(cfg, partial);                    // partial already carries null
  this.#engine.update(cfg);
}

// The same step outside a component (what getEngineConfig() calls):
import { collectEngineConfig } from '@keenmate/web-components-core';
const cfg = collectEngineConfig(bag, { exclude: ['theme'] });

// Engine side — treat null as a real value, per field:
if (updates.x !== undefined) this._x = updates.x;          // clearable: null clears
if (updates.y !== undefined) this._y = updates.y ?? DEFAULT;// defaulted: null → default

            

                
MemberWhereWhat

clearableConfigKeysprotected getterThe configKeys whose null means “clear”. Derived once from the input table; empty without one.

deriveClearableKeys(defs)main indexThe set of clearable configKeys for an input table.

                    
isClearableInput(def)main indexOne row: default: null, or a clearable converter.

                    
isClearableConverter(converter, attribute?)main indexProbes the converter: validate(null) is true (or there is no validate), or fromAttribute(null) returns null. A converter that throws counts as not clearable.

                
            

            

                Inputs that admit null: toText({ isNullable: true }), toBool('tristate'),
                toFunction(), toEnum(values, { isNullable: true }) with no default, a converter with no
                validate, and any row with default: null. Everything else unsets to
                '', 0, false or [], so null never lands in its config.
            

            

                
Never strip the null

                Don't delete null keys from the engine config: the clear would never reach the engine. An
                engine field that can't hold null takes a ?? DEFAULT in its merge instead.
