PO01 · Playground

A popover is a panel that floats next to another element (the reference, such as a button or an input) and stays until something closes it. Compare a tooltip, which shows and hides by itself on hover, and a menu (/menu), which is a ready-made list with its own keyboard handling. A popover's content is yours; core moves it out of the component (so no overflow: hidden clips it), places it next to the reference, keeps it there while the page scrolls, and optionally closes it. It is not the browser's popover attribute.

One popover, every option live. createPopover({ reference, panel }) returns { open, close, update, isOpen, destroy }; the panel is portaled to <body> and positioned by anchor(). Change any control — the popover rebuilds with the new options (and reopens if it was open). Open it, then scroll it near the bottom edge to watch flip and lockPlacement: 'freeze' behave. It closes on Escape or a click outside (shouldCloseOnEscape / shouldCloseOnOutsideClick).

matchWidth: what to look for
With the 360px reference and the long content toggle, watch all four: none = natural content width (ignores the reference); min = at least 360px (grows for wider content); max = at most 360px (shrinks for narrower content, wraps when wider); exact = always 360px. So with the content narrower than 360px, none=max (both narrow) and min=exact (both 360px); with the content wider, it flips: none=min (both grow) and max=exact (both clamp to 360px). min = max(reference, content), max = min(reference, content).

PO02 · Nested popovers (a dialog with two pickers)

Popovers that close on Escape / an outside press join one page-wide overlay tree. A popover opened from inside another one becomes its child: core finds the parent by looking for the open panel that contains the trigger, so there is nothing to wire up. Below, a "dialog" popover holds two simulated multiselects, each opening its own list popover.

Try it — the log shows every onClose(reason):

  • Open Colour, then Size → only the Colour list closes (overlay: a sibling opened); the dialog stays open.
  • Click the dialog's own body → only the open list closes (outside-click).
  • Escape → closes one level per press, deepest first; focus returns to that level's trigger.
  • Pick an option → that list closes (api), the dialog stays.
  • Close the dialog (its button, or a press outside everything) → an open list closes with it, child first (parent / outside-click).

PO03 · API summary

import { createPopover } from '@keenmate/web-components-core/positioning';

const pop = createPopover({
  reference,                 // element (or VirtualElement) to anchor to
  panel,                     // the panel element to position + portal
  container,                 // default: the open modal <dialog> / :popover-open around the reference, else body
  inheritThemeFrom: false,   // default: the reference; false when the panel stays in your shadow root
  visibleClass: 'is-open',   // added on open (hidden by visibility until placed: no flash at 0,0), removed on close
  shouldKeepMounted: true,   // the panel stays where you put it; open / close only toggle visibleClass
  isAnchored: true,          // false: open unpositioned (fullscreen / modal); switch with setAnchored()
  shouldCloseOnEscape: true,       // close on Escape (deepest open overlay only)
  shouldCloseOnOutsideClick: true, // close on a press outside the panel and the reference
  getInsideElements: () => [hint], // more elements a press on doesn't count as outside
  returnFocusTo: input,      // focus target after Escape (default: the reference; null = none)
  shouldCloseOnScroll: true, // a scroll outside the panel (page or a scroller around the reference)
  shouldCloseOnResize: true, // a window resize
  overlayGroup: 'menus',     // opening another overlay of the group closes this one
  onClose(reason) {},        // every close: 'escape' | 'outside-click' | 'overlay' | 'parent' | 'scroll' | 'resize' | 'reference-removed' | 'api'
  // Every shouldCloseOn* also takes a function, asked each time: () => !hasStagedSelection

  // Every anchor() option is forwarded as given:
  placement: 'bottom-start', // default 'bottom-start'
  offset: 4,                 // px gap (default: --base-dropdown-offset, else 4)
  matchWidth: 'min',         // 'min' | 'exact' | 'max' | false — size against the reference width
  lockPlacement: 'freeze',   // 'initial' = return to initial on overflow; 'freeze' = flip once then pin
  shouldFlip: true, shift: 8, // middleware toggles
  fallbackPlacements: ['top-start', 'bottom-end'], // what flip tries, in order
  onPlaced(placement) {},    // resolved placement callback
});

pop.open(); pop.close(); pop.update(); pop.isOpen; pop.destroy();
pop.setAnchored(false);   // e.g. the phone layout: still open, now placed by your CSS
pop.reanchor();           // async content changed the height: pick the side again (lockPlacement 'freeze')
pop.claimCurrentClick();  // from an API method a page button outside the panel calls: this click doesn't close it
// reference may be a function: () => currentAnchorElement, asked at each open / reanchor

container may be a ShadowRoot (the panel keeps the component's styles). See the anchor page for every forwarded option.
