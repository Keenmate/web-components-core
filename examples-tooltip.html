TT02 · Follow-cursor & the fixed bug

With followCursor: true the tooltip anchors to a VirtualElement tracking the pointer instead of the trigger. Each card in the pyramid below has its own follow-cursor tooltip — sweep the pointer across them to watch the tooltip hand off from one element to the next, and hover any single card and hold still through the show delay: it must appear next to the cursor, not pinned to that card's corner.

The bug this proves fixed
The pointer-tracking mousemove listener used to attach only inside show(), which runs after the delay. A stationary hover fired no mousemove during the delay, so the cursor rect was still undefined at show time and the virtual element fell back to the trigger's full rect — pinning the tooltip to the corner. The rect is now seeded on mouseenter and tracked through the delay, so every card in the pyramid seeds its own cursor rect the instant you enter it — even mid-sweep.

TT03 · The <tooltip-card> component

A real BlissElement: its knobs live in a static inputs table (tooltip-text, placement, follow-cursor, show-delay — all on:'reinit'), and it wires the tooltip through connect() / disconnect() / reinit(). Change a control (or edit the element's attributes in devtools) — the tooltip rebuilds live.

This trigger sits at the bottom of a tall box, so when it's near the viewport's bottom edge its bottom preference has no room below and flips up to top — the flip() middleware in action. (Scroll so the trigger is low in the window, then hover.)

TT05 · API summary

import { createTooltip } from '@keenmate/web-components-core/positioning';

const tip = createTooltip({
  trigger,                 // HTMLElement — hover/focus on it toggles the tooltip
  content: 'Hello',        // string | HTMLElement
  placement: 'top',        // Placement (default 'top')
  offset: 8,               // px gap (default 8)
  delay: { show: 400, hide: 0 },   // number | { show?, hide? }
  followCursor: true,      // anchor to & track the pointer (default false)
  container: shadowRoot,   // mount target (default document.body)
  cssClass: 'demo-tt',     // class(es) on the tooltip element
  visibleClass: 'is-visible',      // toggled while shown (default 'is-visible')
  onBeforeShow() {},       // dismiss an overlapping tooltip, etc.
});

tip.show(); tip.hide(); tip.destroy();   // imperative control + teardown
tip.element;  tip.isVisible;             // the tooltip node + state
Focus has no cursor
A keyboard-focus show has no pointer, so followCursor correctly falls back to the trigger rect there.
