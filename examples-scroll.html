SC02 · Alignment, a sticky header and smooth scrolling

A component with its own scroller and a sticky header. nearest (the default) moves only as far as needed, so a visible row stays put and no scrollTo() runs at all; start / center / end align the row. The container's scroll-padding-top keeps start clear of the header. Turn it off and the header covers the row.

Sticky headers are CSS
Like native scrolling, the helper honours the container's scroll-padding and the row's scroll-margin, so a component reserves room for its sticky header in its stylesheet instead of passing an offset.

SC03 · Finding the container across shadow DOM and slots

findScrollContainer() walks up the tree the browser lays out: out of a shadow root to its host, and from slotted content into its slot. Left: rows inside a component's shadow root, the scroller is the page's panel around the component. Right: the page's own rows slotted into <core-demo-slot-box>, the scroller is inside that component's shadow root. <html> and <body> never count, and neither does overflow: hidden: the last button switches the left panel to it for one call.

SC04 · shouldRevealContainer — when the list itself is off-screen

Scrolling only the container is right for keyboard moves: the focused list is on screen. A jump from somewhere else (a search box, a link) can target a list the user can't see; the list scrolls and nothing visible happens. shouldRevealContainer: true first brings the container into the viewport. These buttons target row 55 of the SC02 list, which is above this card. 

scrollIntoContainer(row, { block: 'center', behavior: 'smooth', shouldRevealContainer: true });

SC05 · API

import { findScrollContainer, scrollIntoContainer } from '@keenmate/web-components-core';

findScrollContainer(el, {
  stopAt,       // Element — stop the walk here (exclusive); default: walk up to <body>
  axis,         // 'y' (default) | 'x' | 'both' — the axis that must actually scroll
});             // → the nearest scrolling ancestor (flat tree), or null = only the page scrolls

scrollIntoContainer(el, {
  block,        // 'nearest' (default) | 'start' | 'center' | 'end'
  inline,       // same values, horizontal; default 'nearest'
  behavior,     // 'auto' (default, instant) | 'smooth'
  container,    // scroll this one instead of searching
  stopAt, axis, // passed to findScrollContainer()
  shouldRevealContainer, // also bring the container into the viewport; default false
});             // → the container it scrolled, or null (page fallback, or nothing scrolled)

No container found: the page scrolls with window.scrollTo() and the same alignment rules. With stopAt set and no container below it, nothing scrolls. Nothing to move: no scrollTo() call at all.
