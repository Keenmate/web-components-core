DL01 · confirmDialog and promptDialog instead of the browser popups

The browser's window.confirm / window.prompt can't be styled or translated and freeze the page's scripts while open. The core versions return a Promise, follow the theme and the motion level, and take their button texts from labels. Under 480px wide they open as a bottom sheet. Try both rows and compare.

Core:
Browser: 
import { confirmDialog, promptDialog } from '@keenmate/web-components-core/dialog';

if (await confirmDialog({ title: 'Delete row?', message: 'This cannot be undone.', isDanger: true, confirmLabel: 'Delete' })) { … }

const url = await promptDialog({
  title: 'Image URL', value: 'https://',
  validate: (v) => (/^https:\/\/.+/.test(v) ? null : 'Must start with https://'),  // keeps it open
});                                                                                // null = cancelled

DL02 · openDialog — your buttons, your content

Any set of buttons (the dialog resolves with the pressed one's value) and any content node after the message. beforeCloseCallback returning false keeps it open — here the Save button is refused until the name is filled in. ✕, Escape, the phone Back gesture and a click on the backdrop resolve null; with isDismissible: false only the buttons close it. 

import { openDialog } from '@keenmate/web-components-core/dialog';

const choice = await openDialog({
  title: 'Unsaved changes',
  message: 'Save before closing?',
  actions: [
    { value: 'discard', label: 'Discard', isDanger: true },
    { value: 'cancel', label: 'Keep editing' },
    { value: 'save', label: 'Save', isPrimary: true },
  ],
}).result;                                  // 'save' | 'discard' | 'cancel' | null

DL03 · startModalSession() on a component's own panel

<core-demo-modal> renders its own panel in its shadow root (like a date picker's centered modal). One call does the rest: the page behind goes inert (try clicking or tabbing to it), Tab cycles inside, focus moves in and comes back to the button, page scroll is locked. The panel opens a dropdown of its own: Escape closes the dropdown first, the panel on the second press. Core never closes anything itself — dismissCallback(reason) tells the component, which closes and calls end(). 

import { startModalSession } from '@keenmate/web-components-core';

open() {
  this.#panel.hidden = false;                    // z-index: Z_INDEX.modal
  this.#modal = startModalSession(this.#panel, {
    backdrop: true,                              // or your own element; omit = none
    dismissCallback: (reason) => this.close(reason),   // 'escape' | 'back' | 'backdrop' | …
    trigger: this.#button,                       // focus returns here
  });
}
close() {
  this.#panel.hidden = true;
  this.#modal?.end();                            // every close path, idempotent
}

DL04 · Stacking tiers (Z_INDEX)

One z-index scale for every overlay. A dialog, a phone full-screen sheet or a drawer is the modal tier, so whatever opens inside it — the dropdown in DL03, a tooltip, a toast — is a higher tier and stacks above it with no special case.

TierTokenDefaultFor
 
import { Z_INDEX } from '@keenmate/web-components-core';

const CSS = `.my-sheet { z-index: ${Z_INDEX.modal}; }
             .my-sheet .hint { z-index: calc(${Z_INDEX.tooltip} + 1); }`;   // a sub-layer: never a bare 9999
