TH01 · Page detection — detect once, reuse

Each card below has no signal of its own, so it follows the page. Put a signal on <html>: core reads it once (data-theme, then data-bs-theme, then .dark / .light; <html> before <body>), caches it, and one shared observer re-detects only when a signal attribute changes. Add more cards — the observer count doesn't move. The page's own theme switch (top right) sets the same data-theme on <html>, so it drives these cards too.

"Toggle an unrelated class" changes <html>'s class — the observer fires and re-detects once, but the result is unchanged, so no card's themeChanged × N counter moves.

TH02 · setThemeMode() — force every component

A forced mode wins over detection everywhere (page and theme-source). While forced, the observers pause — there is nothing to detect, so "observing now" drops to 0 and the TH01 signal picker has no effect. auto re-detects once and resumes.

getThemeMode(): auto

TH03 · Per-instance data-theme — highest priority

data-theme on the component itself is pure component CSS, declared after the data-context-theme rules, so it beats the page and a global force. Try setThemeMode('dark') above: the first card stays light.

TH04 · theme-source — read a section instead of the page

Page-level detection doesn't see a signal on a wrapper <div> (Bootstrap allows data-bs-theme per section). theme-source points a component at one: a selector (nearest matching ancestor, else first match in the document), closest (nearest ancestor carrying a signal at connect), or an Element (property). Components sharing a source share one cache and one observer; a source without a signal falls back to the page.

<div id="panel" data-bs-theme="…">
Why not walk every ancestor by default?
That is what :host-context() did (in Chromium only). Watching arbitrary ancestors would mean observing the whole page; page-level detection plus an explicit theme-source for the rare section case keeps it to one observer per watched element.

TH05 · A portaled panel in a themed section

A dropdown or popover is often moved to <body> so no overflow clips it. There it no longer sits under the component, so anchor() / createPopover() copy the theme onto it from inheritThemeFrom (for createPopover() the reference by default). The panel then reads only its own attributes, like the component does.

The section below says data-theme="dark", but the card in it is light: its theme-source points at the light signal above the section, and core wrote that into the card's data-context-theme. The panel has to match the card, not the section. Above the nearest host that carries data-context-theme, a data-theme / data-bs-theme is not copied (core already folded the page or section signal into the host's context). The host's own data-theme is still copied: it is the per-instance switch, and it wins.

Try it. Press Open the panel on the card (again, or Esc, closes it): it reads data-context-theme: light, no data-theme, and renders light next to the light card in the dark section. Then set the card's own data-theme to dark: the card turns dark and the panel (reopened, as the theme is copied when it opens) follows it. setThemeMode() in TH02 moves both together.

theme-source target: #th05-source[data-theme="light"]
<div data-theme="dark"> (a dark section)
import { createPopover } from '@keenmate/web-components-core/positioning';

const popover = createPopover({
  reference: button,            // inside the component's shadow root
  panel,                        // mounted in <body> on open
  inheritThemeFrom: this,       // the component host (the default is the reference)
});
// <div data-theme="dark">                                 section: NOT copied (above the host)
//   <my-el data-context-theme="light" [data-theme="…"]>  copied: the context, and the host's own data-theme
// → <body> > .panel[data-context-theme="light"]

/* the panel's CSS reads its own attributes, like the component's */
.panel[data-context-theme="dark"] { color-scheme: dark; }
.panel[data-theme="dark"]         { color-scheme: dark; }   /* per-instance, declared last */

TH06 · API & component CSS

APIWhat it does
setThemeMode(mode)Force every component to 'dark' or 'light'; 'auto' goes back to detection. While forced, the observers pause.
getThemeMode()'auto' | 'dark' | 'light'.
getThemeContext(host?, source?)The effective scheme right now: the forced mode, else the detected one (the source element's signal, else the page). 'dark' | 'light' | null.
observeThemeContext(host, source, cb, { shouldFireImmediately? })Calls cb(scheme) now (unless shouldFireImmediately: false), then only when the effective scheme changes. The source is resolved once. Returns the unsubscribe. BlissElement does this for you: hook themeChanged(scheme).
readThemeSignal(el)The signal on one element: data-theme, then data-bs-theme, then .dark / .light. Only dark / light count; else null.
resolveThemeSource(host, source)The element a source points at for host, or null for the page (also for <html> / <body> and an invalid selector).
THEME_CONTEXT_ATTRIBUTE · THEME_SOURCE_ATTRIBUTE'data-context-theme' (what core writes on the host) · 'theme-source' (the attribute every BlissElement reads).
anchor(panel, reference, { inheritThemeFrom }) · createPopover({ inheritThemeFrom }) · openMenu(…, { inheritThemeFrom })Copy the theme onto a panel moved out of the component (/positioning, /menu; TH05): the nearest data-theme, data-bs-theme, data-context-theme and data-motion, but data-theme / data-bs-theme only up to the nearest host carrying data-context-theme. Restored when the anchor is destroyed. createPopover() defaults to the reference; false copies nothing.
TypesColorScheme ('dark' | 'light'), ThemeMode (ColorScheme | 'auto'), ThemeSource (string | Element | null), ThemeListener, ObserveThemeContextOptions.
 
import { setThemeMode, getThemeMode, getThemeContext } from '@keenmate/web-components-core';

setThemeMode('dark');   // force every component; 'light' | 'auto' (detect)
getThemeMode();         // 'auto' | 'dark' | 'light'
getThemeContext();      // the effective page scheme: forced mode, else detected; 'dark' | 'light' | null

// Per component (every BlissElement):
//   <my-el data-theme="dark">           force this one (component CSS, wins)
//   <my-el theme-source="closest">      read the nearest signalled ancestor
//   <my-el theme-source=".admin-panel"> read a chosen element
//   el.themeSource = someElement;        property form
//
// In a component: override themeChanged(scheme) for JS-side theming;
// static hasThemeContext = false opts out.
/* Component dark-mode.css — works in every browser */
:host([data-context-theme="dark"])  { color-scheme: dark; }
:host([data-context-theme="light"]) { color-scheme: light; }
/* per-instance forcing, declared last so it wins */
:host([data-theme="dark"])  { color-scheme: dark; }
:host([data-theme="light"]) { color-scheme: light; }
