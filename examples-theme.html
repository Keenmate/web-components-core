TH01 · Page detection — detect once, reuse

Each card below has no signal of its own, so it follows the page. Put a signal on <html>: core reads it once (data-theme, then data-bs-theme, then .dark / .light; <html> before <body>), caches it, and one shared observer re-detects only when a signal attribute changes. Add more cards — the observer count doesn't move. The page's own theme switch (top right) sets the same data-theme on <html>, so it drives these cards too.

Only real changes notify
"Toggle an unrelated class" changes <html>'s class — the observer fires and re-detects once, but the result is unchanged, so no card's themeChanged × N counter moves.

TH02 · setThemeMode() — force every component

A forced mode wins over detection everywhere (page and theme-source). While forced, the observers pause — there is nothing to detect, so "observing now" drops to 0 and the TH01 signal picker has no effect. auto re-detects once and resumes.

getThemeMode(): auto

TH03 · Per-instance data-theme — highest priority

data-theme on the component itself is pure component CSS, declared after the data-context-theme rules, so it beats the page and a global force. Try setThemeMode('dark') above: the first card stays light.

TH04 · theme-source — read a section instead of the page

Page-level detection doesn't see a signal on a wrapper <div> (Bootstrap allows data-bs-theme per section). theme-source points a component at one: a selector (nearest matching ancestor, else first match in the document), closest (nearest ancestor carrying a signal at connect), or an Element (property). Components sharing a source share one cache and one observer; a source without a signal falls back to the page.

<div id="panel" data-bs-theme="…">
Why not walk every ancestor by default?
That is what :host-context() did (in Chromium only). Watching arbitrary ancestors would mean observing the whole page; page-level detection plus an explicit theme-source for the rare section case keeps it to one observer per watched element.

TH05 · API & component CSS

import { setThemeMode, getThemeMode, getThemeContext } from '@keenmate/web-components-core';

setThemeMode('dark');   // force every component; 'light' | 'auto' (detect)
getThemeMode();         // 'auto' | 'dark' | 'light'
getThemeContext();      // the detected page scheme: 'dark' | 'light' | null

// Per component (every BlissElement):
//   <my-el data-theme="dark">           force this one (component CSS, wins)
//   <my-el theme-source="closest">      read the nearest signalled ancestor
//   <my-el theme-source=".admin-panel"> read a chosen element
//   el.themeSource = someElement;        property form
//
// In a component: override themeChanged(scheme) for JS-side theming;
// static hasThemeContext = false opts out.
/* Component dark-mode.css — works in every browser */
:host([data-context-theme="dark"])  { color-scheme: dark; }
:host([data-context-theme="light"]) { color-scheme: light; }
/* per-instance forcing, declared last so it wins */
:host([data-theme="dark"])  { color-scheme: dark; }
:host([data-theme="light"]) { color-scheme: light; }
