Environment & responsive rules

The shared environment facts (getEnvironment(), classifyDevice(), the two observe channels), the resolvePresentation() policy, and the responsive rules every BlissElement with an input table takes — page-wide, per tag and per instance. See SPEC §6.7 and §12.9. Resize the window (or open devtools device emulation) to watch everything flip.

RS01 · Environment snapshot, live

getEnvironment() is a synchronous read of the current snapshot. Two values matter most and they are different axes: classifyDevice(env) decides by capability first — a device whose primary pointer is not touch (isTouchPrimary = (pointer: coarse) and not (hover: hover)) is desktop at any width; only a touch-primary device looks at its shorter side (below TABLET_MIN_SHORT_SIDE = 600 → mobile, else tablet). env.breakpoint is the plain window-width bucket: mobile ≤ 768, tablet ≤ 1024, then desktop — lines taken once from the --base-breakpoint-mobile / --base-breakpoint-tablet tokens when the page defines them, and configureBreakpoints() always wins over the tokens. Two channels deliver changes: observeEnvironment (discrete — fires only when a category flips: breakpoint, orientation, pointer / hover, device class) and observeViewport (continuous — raw size changes, throttled to about one call per 30 ms). Drag the window edge: the continuous counter runs, the discrete one moves only when you cross a line.

The iPad-portrait case

                    An iPad in portrait is 768 × 1024 and touch-primary: its short side (768) is ≥ 600, so it is a
                    tablet — but 768 is inside the mobile width bucket. That is why responsive
                    maps have two axes (RS03) and why deviceClass, not width, is the axis to key mobile/tablet UX on.
                    A desktop window narrowed to 700 px is the opposite: desktop device, mobile bucket.
                

            

            
import { getEnvironment, observeEnvironment, observeViewport, classifyDevice, configureBreakpoints } from '@keenmate/web-components-core';

const env = getEnvironment();          // { pointer, canHover, isTouchPrimary, orientation, viewportWidth, breakpoint, os, … }
classifyDevice(env);                   // 'mobile' | 'tablet' | 'desktop'

const offDiscrete   = observeEnvironment((env) => …, { shouldFireImmediately: false }); // category flips only
const offContinuous = observeViewport((env) => …,    { shouldFireImmediately: false }); // every size change, ≈30 ms throttle
configureBreakpoints({ mobile: 640, tablet: 1100, desktop: Infinity });                  // global, beats the tokens

        


        
        
        
        

            
RS02 · resolvePresentation(mode, env, map)

            

                The per-component policy on top of the shared classification. A forced mode
                (floating / modal / fullscreen) is returned as-is; auto
                classifies the device and looks the class up in map, falling back per class to
                DEFAULT_PRESENTATION_MAP (mobile → fullscreen, tablet /
                desktop → floating). List only the classes you change. It is a pure function — the table
                runs it against the live snapshot and four simulated ones.

import { resolvePresentation, DEFAULT_PRESENTATION_MAP } from '@keenmate/web-components-core';

protected override environmentChanged(env) {
  // "on a tablet, use a modal" — phone and desktop keep the defaults:
  this.setPresentation(resolvePresentation(this.presentation, env, { tablet: 'modal' }));
}

        


        
        
        
        

            
RS03 · A responsive map: { device, breakpoint }

            

                <core-demo-rs-map> is a real BlissElement with three inputs
                (layout is on: 'reinit', the others on: 'update'). Its instance map
                (the JSON responsive attribute) has both axes. Within one map the
                breakpoint entry applies first and the device entry over it — device wins on the same key.
                this.config and the getters report the effective config; a callback's
                ctx.config is the base (defaults + attributes + properties). An instance map
                beats the element's own attributes, so set a base columns below: on a wide desktop (no
                desktop entry) the base shows through; narrow the window under 768 px and the map takes
                over again — a key a rule stops returning goes back to its base value.

RS04 · Precedence: page → tag → instance

            

                Seven layers, later wins, key by key. Page rules lose to anything set explicitly on the
                element (an attribute or assigned property); the element's own map and callback beat everything.
                An instance rule returning null means “ignore every page rule” (the instance's own values
                still apply). Overrides never reflect — watch the attribute column. Untick a layer and
                the key falls back to the next one, or the base. Every map below lists all device classes, so it
                applies at any size.

RS05 · Callbacks: your own widths

            

                Maps key on the two discrete axes only. Anything finer — your own width, orientation, a device class
                and a width — goes in a callback. While any callback layer applies, the element also listens on
                the continuous viewport channel, so env.viewportWidth < 600 is re-checked
                between breakpoint lines. The result is diffed: the callback runs on every (throttled) size change, but
                update() only fires when the returned values actually change.

RS06 · API summary

            

                
APIWhat it does

                
                    
getEnvironment()Synchronous EnvironmentSnapshot: pointer, hasCoarsePointer, canHover, isTouchPrimary, orientation, viewportWidth/Height, breakpoint, os, isApple, isAndroid.

                    
observeEnvironment(cb, { shouldFireImmediately? })Discrete channel — category flips only. Returns the unsubscribe. BlissElement hook: environmentChanged(env).

                    
observeViewport(cb, opts)Continuous channel — size changes, throttled ≈30 ms (leading + trailing). Hook: viewportChanged(env).

                    
configureBreakpoints(map)Redefine the width buckets globally (beats the --base-breakpoint-* tokens). Default { mobile: 768, tablet: 1024, desktop: Infinity }.

                    
classifyDevice(env)'mobile' | 'tablet' | 'desktop' — not touch-primary → desktop; else short side < TABLET_MIN_SHORT_SIDE (600) → mobile, else tablet.

                    
resolvePresentation(mode, env, map?)Forced mode as-is; auto → map[deviceClass] ?? DEFAULT_PRESENTATION_MAP[deviceClass].

                    
window.components.responsive / .responsiveCallbackPage-wide rule layers (non-enumerable; unknown keys skipped silently). Set to null to clear.

                    
window.components[tag].responsive / .responsiveCallbackPer-tag layers (installed by registerComponent(); a pre-existing entry is adopted).

                    
el.responsive / responsive='{…}'Instance map { device?, breakpoint? }; breakpoint entry first, device entry over it. A null entry = ignore page rules.

                    
el.responsiveCallback = (ctx) => …Instance callback; ctx = { env, deviceClass, breakpoint, element, component, config } (config = frozen base). Return a partial, undefined (nothing) or null (ignore page rules). A throw is logged and treated as undefined.

                    
TypesResponsiveMap<C>, ResponsiveMapAxis, ResponsiveContext<C>, ResponsiveCallback<C>, EnvironmentSnapshot, DeviceClass, Presentation, ResolvedPresentation, PresentationMap.

                
            

            

                
Rules of the road

                Precedence: global map → global callback → per-tag map → per-tag callback → instance attributes /
                properties → instance map → instance callback. Values are validated by each input's converter (invalid →
                warn + skip); responsive, responsiveCallback and shouldDefer are
                reserved. Overrides never reflect and never count as explicit. Rules are applied before the first
                reinit() (no flash of the desktop layout); a defer-held element gets them at
                release().
