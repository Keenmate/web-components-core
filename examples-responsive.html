RS01 · Environment snapshot, live

getEnvironment() is a synchronous read of the current snapshot. Two values matter most and they are different axes: classifyDevice(env) decides by capability first — a device whose primary pointer is not touch (isTouchPrimary = (pointer: coarse) and not (hover: hover)) is desktop at any width; only a touch-primary device looks at its short side (below TABLET_MIN_SHORT_SIDE = 600 → mobile, else tablet). The short side is min(viewport width, screen short side), not the viewport height — so a soft keyboard that shrinks the height can't turn a tablet into a phone. env.breakpoint is the plain window-width bucket: mobile ≤ 768, tablet ≤ 1024, then desktop — lines taken once from the --base-breakpoint-mobile / --base-breakpoint-tablet tokens when the page defines them, and configureBreakpoints() always wins over the tokens. Two channels deliver changes: observeEnvironment (discrete — fires only when a category flips: breakpoint, orientation, pointer / hover, device class) and observeViewport (continuous — raw size changes, throttled to about one call per 30 ms). Drag the window edge: the continuous counter runs, the discrete one moves only when you cross a line.

The iPad-portrait case

                    An iPad in portrait is 768 × 1024 and touch-primary: its short side (768) is ≥ 600, so it is a
                    tablet — but 768 is inside the mobile width bucket. That is why responsive
                    maps have two axes (RS03) and why deviceClass, not width, is the axis to key mobile/tablet UX on.
                    A desktop window narrowed to 700 px is the opposite: desktop device, mobile bucket.
                

            

            
import { getEnvironment, observeEnvironment, observeViewport, classifyDevice, configureBreakpoints } from '@keenmate/web-components-core';

const env = getEnvironment();          // { pointer, canHover, isTouchPrimary, orientation, viewportWidth, screenShortSide, breakpoint, os, … }
classifyDevice(env);                   // 'mobile' | 'tablet' | 'desktop'

const offDiscrete   = observeEnvironment((env) => …, { shouldFireImmediately: false }); // category flips only
const offContinuous = observeViewport((env) => …,    { shouldFireImmediately: false }); // every size change, ≈30 ms throttle
configureBreakpoints({ mobile: 640, tablet: 1100, desktop: Infinity });                  // global, beats the tokens

        


        
        
        
        

            
RS02 · resolvePresentation(mode, env, map)

            

                The per-component policy on top of the shared classification. A forced mode
                (floating / modal / fullscreen) is returned as-is; auto
                classifies the device and looks the class up in map, falling back per class to
                DEFAULT_PRESENTATION_MAP (mobile → fullscreen, tablet /
                desktop → floating). List only the classes you change. It is a pure function — the table
                runs it against the live snapshot and four simulated ones.

import { resolvePresentation, DEFAULT_PRESENTATION_MAP } from '@keenmate/web-components-core';

// setPresentation() / this.presentation are the component's own (not BlissElement API).
protected override environmentChanged(env) {
  // "on a tablet, use a modal" — phone and desktop keep the defaults:
  this.setPresentation(resolvePresentation(this.presentation, env, { tablet: 'modal' }));
}

        


        
        
        
        

            
RS03 · A responsive map: { device, breakpoint }

            

                <core-demo-rs-map> is a real BlissElement with three inputs
                (layout is on: 'reinit', the others on: 'update'). Its instance map
                (the JSON responsive attribute) has both axes. Within one map the
                breakpoint entry applies first and the device entry over it — device wins on the same key.
                this.config and the getters report the effective config; a callback's
                ctx.config is the base (defaults + attributes + properties). An instance map
                beats the element's own attributes, so set a base columns below: on a wide desktop (no
                desktop entry) the base shows through; narrow the window under 768 px and the map takes
                over again — a key a rule stops returning goes back to its base value.

RS04 · Precedence: page → tag → instance

            

                Seven layers, later wins, key by key. Page rules lose to anything set explicitly on the
                element (an attribute or assigned property); the element's own map and callback beat everything.
                An instance rule returning null means “ignore every page rule” (the instance's own values
                still apply). Overrides never reflect — watch the attribute column. Untick a layer and
                the key falls back to the next one, or the base. Every map below lists all device classes, so it
                applies at any size.

RS05 · Callbacks: your own widths

            

                Maps key on the two discrete axes only. Anything finer — your own width, orientation, a device class
                and a width — goes in a callback. While any callback layer applies, the element also listens on
                the continuous viewport channel, so env.viewportWidth < 600 is re-checked
                between breakpoint lines. The callback also re-runs on every flush (a base value changed) and whenever a
                page rule changes. The result is diffed: the callback runs often, but update() only fires
                when the returned values actually change.

RS06 · Element size: sizeChanged(size)

            

                A component that overrides sizeChanged(size) is told its own border-box size whenever its
                layout changes (one shared ResizeObserver, throttled ≈30 ms). Use it for
                structural decisions; plain reflow belongs in CSS container queries. The demo below lays
                out one tile per 120px of the width it was told.
            

            

                The size is the layout size: CSS transforms are not applied. Scale the component down
                and change its width: sizeChanged keeps reporting the real width (and the same number of
                tiles), while the visual box from getBoundingClientRect() shrinks with the transform. That
                matters for panels that open with a scale() animation: they used to report a shrunken size
                while animating.
            

            

                
                
                
                
            

            
            

                
            

            

            
class MyPanel extends BlissElement {
  protected override sizeChanged({ width, height }: ElementSize) {
    // layout size (transforms not applied); throttled, deduped
    this.#columns = Math.max(1, Math.floor(width / 120));
    this.#renderTiles();
  }
}

        


        
        
        
        

            
RS07 · container: the component's own width

            

                The third axis of a responsive map is keyed by the component's own width, not the
                window's: narrow (< 480px) · medium (< 768px) · wide.
                The same picker can be wide in the main content and narrow in a sidebar on the same monitor. One rule,
                written once for every picker on the page:
            

            
window.components['core-demo-rs-picker'].responsive = {
  container: {
    narrow: { months: 1, isTodayButtonVisible: false },   // the picker is < 480px
    medium: { months: 2 },
  },
};

            

                
                
            

            
Drag the slider (or the bottom-right corner of the first box): the picker inside switches
                from 2 months to 1 and loses its Today button the moment its width crosses 480px — the window
                doesn't change.

#trip          { --base-container-narrow: 600px; }   /* one component */

            

                Order inside one map: breakpoint (the window) → container (its own width) →
                device — a later axis wins on the same key. A responsiveCallback gets
                ctx.container and ctx.width too. Plain restyling (padding, a label turning into an
                icon) stays in CSS @container; this axis is for structural changes (the month count, a panel).
            

        


        
        
        
        

            
RS08 · All together: a booking page

            

                One page rule with all three axes, four date fields in a real layout. Click a field: it
                opens the calendar the way the rules say — a dropdown under the field (floating), or on a phone
                a full-screen sheet with the shared header, page scroll locked and the phone Back gesture closing it
                (fullscreen, core startSheetSession). Nothing below is simulated — it reacts to
                your browser:
            

            
    
                
  • breakpoint — resize the browser window (below 768px it is mobile). The layout
                    reflows too: the sidebar drops under the main column and gets wider, so its picker changes
                    container at the same time.
    • 
                
  • container — each picker's own width; Departure / Return share one row, so they are
                    narrower than Trip dates.
    • 
                
  • device — open the devtools device toolbar (Ctrl+Shift+M), pick a
                    phone and reload: device becomes mobile and every picker opens full-screen.
    • 
            

            
window.components['core-demo-rs-booking'].responsive = {
  // the WINDOW: how many months the page can afford
  breakpoint: { tablet: { months: 2 }, mobile: { months: 1 } },
  // the PICKER's own box: a narrow one is a compact one (overrides the window on the same key)
  container: {
    narrow: { months: 1, isTodayButtonVisible: false, isClearButtonVisible: false },
    medium: { isClearButtonVisible: false },
  },
  // a PHONE: open full-screen — there is room for Today again (overrides both)
  device: { mobile: { presentation: 'fullscreen', isTodayButtonVisible: true } },
};
// order: breakpoint → container → device — a later axis wins on the same key.
// The picker's own default: 3 months, Today + Clear shown, opens floating.

RS09 · API summary

            

                
APIWhat it does

                
                    
getEnvironment()Synchronous EnvironmentSnapshot: pointer, hasCoarsePointer, canHover, isTouchPrimary, orientation, viewportWidth/Height, screenShortSide (shorter side of the screen; undefined without one), breakpoint, os, isApple, isAndroid.

                    
observeEnvironment(cb, { shouldFireImmediately? })Discrete channel — category flips only. Returns the unsubscribe. BlissElement hook: environmentChanged(env).

                    
observeViewport(cb, opts)Continuous channel — size changes, throttled ≈30 ms (leading + trailing). Hook: viewportChanged(env).

                    
sizeChanged(size) · observeElementSize(el, cb, opts)The element's border-box layout size (transforms not applied), via one shared ResizeObserver; deduped. opts: shouldFireImmediately (default true), throttleMs (default 30, 0 = off). The hook is override-gated (RS06).

                    
configureBreakpoints(map)Redefine the width buckets globally (beats the --base-breakpoint-* tokens). Default { mobile: 768, tablet: 1024, desktop: Infinity }. Page-wide across every bundled copy of core: it fires BREAKPOINTS_CHANGE_EVENT ('km-breakpoints-change') on document so the other copies recompute.

                    
classifyDevice(env)'mobile' | 'tablet' | 'desktop' — not touch-primary → desktop; else min(viewportWidth, screenShortSide) < TABLET_MIN_SHORT_SIDE (600) → mobile, else tablet. Without a screen size it uses the shorter viewport side.

                    
resolvePresentation(mode, env, map?)Forced mode as-is; auto → map[deviceClass] ?? DEFAULT_PRESENTATION_MAP[deviceClass].

                    
createPresentationContext(presentation)Builds a PresentationContext — { presentation, isFullscreen, isModal } — to spread into a render callback's context, so a custom renderer can adapt to how the panel is shown.

                    
window.components.responsive / .responsiveCallbackPage-wide rule layers (non-enumerable; unknown keys skipped silently). Set to null to clear.

                    
window.components[tag].responsive / .responsiveCallbackPer-tag layers (installed by registerComponent(); a pre-existing entry is adopted).

                    
el.responsive / responsive='{…}'Instance map { device?, breakpoint? }; breakpoint entry first, device entry over it. A null entry = ignore page rules.

                    
el.responsiveCallback = (ctx) => …Instance callback; ctx = { env, deviceClass, breakpoint, element, component, config } (config = frozen base). Return a partial, undefined (nothing) or null (ignore page rules). A throw is logged and treated as undefined.

                    
TypesResponsiveMap<C>, ResponsiveMapAxis, ResponsiveContext<C>, ResponsiveCallback<C>, EnvironmentSnapshot, EnvironmentListener, ObserveEnvironmentOptions, PointerAccuracy, Orientation, OS, BreakpointMap, DeviceClass, ElementSize, ElementSizeListener, ObserveElementSizeOptions, Presentation, ResolvedPresentation, PresentationMap, PresentationContext.

                
            

            

                
Rules of the road

                Precedence: global map → global callback → per-tag map → per-tag callback → instance attributes /
                properties → instance map → instance callback. Values are validated by each input's converter (invalid →
                warn + skip); responsive, responsiveCallback and shouldDefer are
                reserved. Overrides never reflect and never count as explicit. Rules are applied before the first
                reinit() (no flash of the desktop layout); a defer-held element gets them at
                release().
