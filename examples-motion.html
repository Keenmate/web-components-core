MO02 · Closest wins: element → section → page

Every place that can set a level is a layer, and the closest one that is set wins, exactly like a CSS property inherits: a component's own motion → the nearest data-motion around it → the page → the component's own speed. auto means "no level here": core writes nothing for it, so the next layer out decides.

The page level (window.components.motion) is written once, on <html data-motion>, never on the components, so any section can still override it for what's inside. An author-written <html data-motion> is the same layer: the page level replaces it while set, and auto puts it back.

MO03 · Animating out, and switching off one animation

            

                motion is the one "animate or not" switch. Components animate by default; at
                none (or OS reduced motion) every decorative animation, i.e. one that shows
                a change happening, becomes instant: appear / disappear, expand / collapse, a size change,
                a highlight fade, smooth scrolling. motion never changes timers
                (a feedback time, a debounce, a tooltip delay keep their time) or activity indicators (a
                loader keeps spinning — the only sign something runs). Components have no is…AnimationEnabled properties.
            

            

                To switch off just one animation, set its duration token to 0s, anywhere
                the cascade reaches. Its default points at a speed token, so motion still wins over it.
                Below, the list items animate in and out with core animateOut(); the knob next to them is
                a different animation.
            

            
    
                
  • Remove → the last item animates out, then leaves the page (doneCallback).
    • 
                
  • Add while an item is still closing → cancel(): it comes back instead.
    • 
                
  • data-motion="none" on the area → everything is instant, no waiting.
    • 
                
  • The checkbox → only the items are instant; the knob still slides.
    •

out.cancel();                          // re-added mid-close: the class comes off, doneCallback never runs

        


        
        
        
        

            
MO04 · API summary

            

                
APIWhat it does

                
                    
motion input · motion="…"On every BlissElement: auto (default) | none | snappy | smooth. Reflects. Core writes the element's own level to data-motion on the host; auto writes nothing. An invalid value warns and keeps the previous one.

                    
window.components.motionThe page level (non-enumerable). Written once on <html data-motion>; auto removes it again (or puts back an author value). An invalid value reads as auto.

                    
getPageMotion()The page level ('auto' when unset).

                    
observePageMotion(cb)Calls cb(level) when the page level changes. Returns the unsubscribe.

                    
MOTION_VALUES['auto', 'none', 'snappy', 'smooth'].

                    
MOTION_PRESETSThe four speeds per level, as --base-duration-fast / -normal / -medium / -slow: none 0s · 0s · 0s · 0s; snappy 0.05s · 0.08s · 0.12s · 0.15s; smooth 0.15s · 0.25s · 0.35s · 0.45s. --base-scroll-behavior is auto for none, smooth for the others.

                    
MOTION_CSSThe [data-motion] rules that set those tokens, plus the prefers-reduced-motion: reduce rule that zeroes them.

                    
adoptMotionStyles(node)Adopts MOTION_CSS into the root node lives in and into its document. Core does this for every element; idempotent.

                    
MOTION_ATTRIBUTE · MOTION_DATA_ATTRIBUTE'motion' (the input) · 'data-motion' (what core writes).

                    
animateOut(elements, { className, doneCallback, shouldSetInert, shouldSetHeightVar })Adds the closing class (a string, or (el) => string per element) and inert, waits for each element's own animationend (gives up after the duration + 50ms), then runs doneCallback — at once when the duration is 0s. Returns { cancel(), finished }; finished resolves true after doneCallback, false when cancelled.

                    
readAnimationMs(el)The longest delay + duration of the element's current CSS animations, in ms; 0 for none.

                    
EXIT_HEIGHT_VAR'--km-exit-height': what shouldSetHeightVar writes (each element's height in px).

                    
TypesMotion, AnimateOutOptions, AnimateOutHandle.

                
            

            

                
Rules of the road

                Closest wins, like CSS inheritance: the element's own motion → the nearest
                data-motion (a section) → the page → the component's own speed. The OS "reduce motion"
                setting always wins. Components animate only through the --base-duration-* /
                --base-scroll-behavior tokens. One animation is switched off by its own
                --<prefix>-<what>-animation-duration: 0s, never by a property.
