MO02 · Closest wins: element → section → page

Every place that can set a level is a layer, and the closest one that is set wins, exactly like a CSS property inherits: a component's own motion → the nearest data-motion around it → the page → the component's own speed. auto means "no level here": core writes nothing for it, so the next layer out decides.

The page level (window.components.motion) is written once, on <html data-motion>, never on the components, so any section can still override it for what's inside. An author-written <html data-motion> is the same layer: the page level replaces it while set, and auto puts it back.

motion input · motion="…"On every BlissElement: auto (default) | none | snappy | smooth. Reflects. Core writes the element's own level to data-motion on the host; auto writes nothing. An invalid value warns and keeps the previous one.

                    
window.components.motionThe page level (non-enumerable). Written once on <html data-motion>; auto removes it again (or puts back an author value). An invalid value reads as auto.

                    
getPageMotion()The page level ('auto' when unset).

Rules of the road

                Closest wins, like CSS inheritance: the element's own motion → the nearest
                data-motion (a section) → the page → the component's own speed. The OS "reduce motion"
                setting always wins. Components animate only through the --base-duration-* /
                --base-scroll-behavior tokens.
