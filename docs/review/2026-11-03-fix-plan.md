# Core fix plan — from the 2026-11-03 review

Source: [`2026-11-03-code-review.md`](2026-11-03-code-review.md) (findings and themes; the decisions are in its §7) and the per-slice reports in [`2026-11-03/`](2026-11-03/).

**Ground rules for every work package (WP):**
- A fix lands with its regression test, unit or e2e, whichever can actually observe it. A test that only passes because jsdom has no layout doesn't count.
- A "core is missing X" claim is checked against the five components before any code is written (grep `C:\Git\KM\web-*`).
- `npm run typecheck`, `npm test` and the Chromium e2e suite pass at the end of each WP. Each WP is one or more commits on `prod`, and its CHANGELOG `[Unreleased]` entry is written as part of the WP.
- Breaking changes get a **BREAKING** CHANGELOG note, with no compatibility aliases.
- Component repos are never edited from here. Component follow-ups go into briefs (WP13).

**Legend:** 🟥 breaking for components or pages · 🟩 no API change · S/M/L = rough size.

## rc18 — no API changes

### WP1 — Throwing code never wedges or leaks, plus the High bugs 🟩 · L — ✅ DONE 2026-11-03

New internal helper `src/internal/safe-invoke.ts`:
- `safeInvoke(fn, args, logCtx)` runs one call, logs any throw through `coreLog`, and returns `{ ok, value }`.
- `notifyAll(listeners, value, logCtx)` loops over the listeners; each throw is logged and the rest still run.

The rules for `BlissElement`:
- A throwing hook never blocks `ready`, the remaining subscriptions, or the balancing teardown.
- The error is still rethrown to whoever flushed (current contract).

| Finding | Fix |
|---|---|
| **E-01** High | Write `motion` back without the reflect guard swallowing the browser's queued attribute replay. Option: defer the write-back to a microtask, or give the guard a name, `#reflectingAttribute = name`, and only skip that name. |
| **V-01** High | `subscribe()` registers the unsubscribe before the first call, and wraps the first call in `safeInvoke`. |
| **L-01** High | `applyAll` checks the level (`normalizeLevel`, which throws or warns) before storing it. An invalid stored level is ignored on read. |
| **D-01** High | `renderLoader` records the added nodes right after drawing (diffing at render time, or a `MutationObserver`-free snapshot taken after the hook returns), not when `remove()` runs. |
| **A-01** High | Submenu open: check a per-level token / `isCollapsed` after the children resolve, before `anchor()`. Never create an anchor for a level that is already collapsed. |
| D-05 | The microtask scheduler runs each task with `safeInvoke`; the first error is rethrown after the batch (or logged). |
| V-06, V-07 | element-size and motion fan-out go through `notifyAll`. |
| E-02 | A retried `reinit()` that calls `flush()` gets a re-entrancy guard (`#isFlushing`), so a nested flush is a no-op that stages. |
| E-03, E-14 | Activation runs the subscriptions in `finally`-style order; `ready` is scheduled after a successful build even if `connect()` / `disabledChanged()` threw. |
| E-06, I-06 | Reflection goes through `safeInvoke`. A throwing `toAttribute` logs, skips that attribute, and doesn't abort the build. |
| E-07 | A throwing `update(partial)` re-stages its keys, so the next flush retries them (same model as the `reinit()` retry). |
| E-08 | `whenReady()` after `destroy()` settles (it rejects with a `DestroyedError`, or resolves — decided in the WP; resolving is my default, to keep "never rejects"). |
| E-09 | The property setter, the pre-upgrade lift and the responsive refresh call `validate` through `safeInvoke`; a throw counts as invalid (warn and keep the previous value). |
| E-12 | `destroy()` during `connect()` or a hook: activation checks `#isDestroyed` after each step and unwinds. |
| D-14 | `computePosition(...).catch(err => coreLog(...))`; the callbacks run inside `safeInvoke`. |
| A-15, A-16 | The menu calls `runAction` with `.catch` and logs; `closeCallback` runs inside `safeInvoke`. `runAction` doesn't reject when `emitAction` throws. |
| I-04 | `runBeforeCallbackSync`: a thenable result warns "async guard used in a sync path — ignored", and its rejection is caught. |

**Tests:**
- One unit regression per row: a throwing hook / listener / task / callback.
- **e2e:** `test/regressions.html` gets markup `<x motion="bogus" label="hi">` before the element is defined. The E-01 regression has to run on the real reaction queue, not only in jsdom.

### WP2 — Page-wide state shared by every copy of core 🟩 · M — ✅ DONE 2026-11-03 (V-08 documented as a limitation; L-15 bundle-set growth left: only repeated createLoggers() of one namespace)

New internal helpers:
- **`sharedState<T>(name, version, init)`** creates the state at `globalThis[Symbol.for('@keenmate/web-components-core:<name>@<version>')]`.
  - **Already-published keys stay exactly as they are**: `km-scroll-lock` and `km-overlay-all-groups` are part of the pure-css contract. They are passed in as an explicit key.
  - A shape change bumps `version`. Two copies on different shapes then don't corrupt each other; they just don't share until both are upgraded.
- **`publishPageSetting(name, { get, set })`** owns the non-enumerable `window.components.*` accessor once. It survives the page replacing `window.components` (V-08) by re-installing on the next core access.

| Finding | Fix |

| V-02 / L-11 | Instance registry and logger-registry `BY_TAG` → `sharedState`. |
| V-03 | A second copy registering an existing tag **merges**: it keeps the first entry and the instances, and warns once with both versions. |
| D-03 / D-19 | `adoptStyles`: checks the root's actual `adoptedStyleSheets` (by sheet identity) instead of a per-copy map. Uses a page-wide sheet cache keyed by `(document, cssText hash)`, so an iframe gets its own sheet. |
| L-02 | The persist-key prefix becomes shared; CORE loggers re-read their level when the prefix changes. |
| L-09 | One CORE bundle per page (shared); `getCategories()` reports all of them. |

## rc19 — the breaking batch

### WP4 — Converter contract (decision 1) 🟥 · M — WP4a ✅ DONE 2026-11-03; WP4b ✅ DONE (E-13 equal-value no-op left as a question) (I-01 is by design: null = "the engine decides", documented by a test; I-09 left: validate cannot transform values)

**WP4a (rc18):**
- strict numbers (`toInt` / `toFloat` / `toList` number items);
- `toBytes` units and strictness (I-11);
- `toCssLength`;
- `fromAttribute` trims everywhere;
- I-01 (a plain `toEnum` honours the row default);
- I-09 (`toText` `''`);
- I-13 (warn on a non-function twin);
- I-14 (classification fix);
- the responsive items (I-05, I-15, I-16, I-17).

**WP4b (rc19):**
- case-insensitive enums;
- I-08 (`undefined` resets to the default);
- I-10 (`toList` escape / JSON form);
- I-07 (`isNullable` rename);
- E-13 (the question about writing an equal value).

The full list:

- **Strict numbers:** `toInt` / `toFloat` / `toList({itemType:'int'|'float'})` match the whole trimmed string (`/^[+-]?\d+$/`, plus a decimal or exponent pattern for float). `"Infinity"` and `"NaN"` are rejected on both paths (I-02).
- **New `toCssLength({ default?, allowNegative? })`:** a bare number becomes px; strings are checked with `CSS.supports('width', v)`, with a regex fallback; invalid values warn and keep the previous value.
- **One contract for every converter (I-12):** `fromAttribute` always trims; enum matching is case-insensitive, and reflection writes the canonical spelling.
- I-01: plain `toEnum` honours the row `default` for a missing attribute; `el.x = null` resets it to the default.
- I-08: **`el.x = undefined` resets an input to its default** on every converter, and clears it from the "explicit" set, so page responsive rules apply again.
- I-09: `toText` treats `''` the same on both paths; `shouldTrim` applies to both paths.
- I-10: `toList` gets an escape (`\,`) or a JSON-array form (`'["a,b"]'`); `[]` reflects as an empty attribute that means empty, not "default"; whitespace-only input → `[]`.
- I-11: `toBytes` accepts `K/KB/M/MB/G/GB/T/TB` and rejects `"1.2.3mb"` and fractional bytes. The binary vs SI question is checked against dropzone's `parseBytes` (binary, 1024) and its `formatFileSize` → **binary by default**, so dropzone can delete its fork.
- I-07: rename `shouldNullOnInvalid` → **`isNullable`**.
- I-13: assigning a non-function to an `on<Name>` twin warns and keeps the previous handler.
- I-14: `clearableConfigKeys` — fix the classification of `toValue` / `toCustom`. Keep the API: it belongs to the rc12 null-clear contract, and its component migration is still pending. Check with the components before removing anything.
- **Responsive:**
  - I-05: responsive overrides run `getBatchValuesCallback`.
  - I-15: a responsive `isDisabled` override is refused with a warning, because disabling must reflect.
  - I-16: one validator; the attribute uses a shared `parseJsonAttribute`.
  - I-17: the page-map warning shows once per page.
- **Open question for this WP:** E-13. Should a property write of an equal primitive (`el.x = el.x`) be a no-op?

**Tests:** a converter matrix (one table-driven test per converter covering whitespace, case, junk, empty, null, undefined, and the round-trip `fromAttribute`∘`toAttribute`); `inputs.spec.ts` gets numeric / list / bytes / css-length attribute cases; `nullclear.spec.ts` gets a tristate `toBool`, a `toFunction` clear and a nullable enum.

### WP5 — Security and search text 🟥 · S — ✅ DONE 2026-11-03 (A-12 `u` flag skipped: typed regexes carry no flags by invariant)

- A-04: **public `escapeHtml()`**. `wrapRanges(text, ranges)` escapes by default (BREAKING: its output changes for callers that passed HTML). Trusted HTML gets `highlightHtml(html, ranges)`, which walks text nodes so a `<mark>` never lands inside a tag or entity.
- A-14: case-insensitive matching uses full case folding (`toLocaleLowerCase` plus a folding table for `İ/ı`, `ß→ss`, `ﬁ→fi`), keeping offset maps so highlights still line up.

- A-11, A-12: word boundaries by code point (`\p{L}\p{M}*`); regexes get the `u` flag.
- A-26: intended behaviour, documented only.
- **Tests:** a search i18n unit file (Turkish, German, Hindi, Japanese, emoji, NBSP); e2e for highlighting on HTML labels.

## Test-gap audit (2026-11-04)

The five test-gap lists (E-23, I-18, V-19, D-29, A-27) were checked scenario by scenario against
the suite; every scenario now has a test or is recorded as no longer applying (map: `test/COVERAGE.md`
§13i). Bugs the new tests found, all fixed:

| From | Fix |
|---|---|
| E-23 | A write staged inside `update()`/`reinit()` before the hook's own `flush()` was stranded (`#flushNow` cancelled the microtask). |
| I-18 | Table check: two events sharing one `on<Name>` property now warn. |
| V-19 | `recompute()` re-entrancy: no stale snapshot after a nested `configureBreakpoints()`; `notifyEach` gains `isSuperseded`. |
| V-19 | Listeners unsubscribed mid-delivery are skipped (`notifyEach` on a Set, element-size fan-out). |
| V-19 | Scroll lock release restores the pinned body (`saved.body`), not the current `document.body`. |
| D-29 | `onDrift` measured in the platform's offset-parent frame (no false report when floating-ui compensated). |
| D-29 | Culprit hint listed `contain` twice. |
| D-29 | Tooltip `focusout` to a node inside the trigger no longer hides / re-anchors. |

Behaviours pinned as current (not bugs): `toList` keeps an empty trailing item (`"a,b,"`; open
question); `word-starts-with` needs the match to start a word (`-b` in `a-b` → none); a keep-open
item in a lazy submenu re-fetches the level; `highlightHtml` decodes a fixed entity set.
