Events & interaction

How a BlissElement talks to the page: typed events through emit() and their on<Name> twins (SPEC §12.5), one contract for every before*Callback, clickable items and the single action event from /actions (§12.12), and the shared context / dropdown menu from /menu (§12.13). Every demo is a small demo element that reports what it does into the timeline under it.

IA01 · emit(): typed events and their twins

A component lists its outward notifications in static events (a bare name, or an EventDef with dispatch overrides) and fires them with the protected this.emit(name, detail). That does three things in order. First it attaches the component context to the detail, in place: controller (the public facade from createController()) and element (the host), both non-enumerable, plus the enumerable extras from eventContext(). So destructuring works, while JSON.stringify and Object.keys see only the data. Then it calls the on<Name> twin (ping → onPing, ping-wide → onPingWide) with the detail, before anything else. A throwing twin is logged and the DOM event still fires. Last, it dispatches a CustomEvent carrying the same object: bubbles: true, composed: false by default. A non-composed event fired inside another component's shadow root stops at that shadow root, so it can't be mistaken for the outer component's. ping-wide sets composed: true in its row to show the difference.

div#demo-ia01-parent (light DOM)
Fire an event to inspect its detail.
type Events = { ping: { count: number }; 'ping-wide': { count: number } };

class Emitter extends BlissElement<Events, EmitterController> {
  static events = ['ping', { name: 'ping-wide', composed: true }];
  protected createController() { return { fire: (n) => this.fire(n), get count() { … } }; }
  protected eventContext() { return { emittedBy: this.id }; }   // enumerable extra
  fire(name = 'ping') { this.emit(name, { count: ++this.count }); }
}

el.onPing = (detail) => { … };                       // twin: called FIRST, with the detail
el.addEventListener('ping', (e) => e.detail);        // same object as the twin got
el.on('ping', (e) => { … });                         // typed addEventListener, returns unsubscribe
const { controller, element, count } = e.detail;     // destructuring works
JSON.stringify(e.detail);                            // '{"count":1,"emittedBy":"…"}' — no controller/element

IA02 · before*Callback: one contract

Every interceptor hook takes one ctx and answers with its return value: false rejects (nothing starts), undefined continues unchanged, and any other value (including null) continues with that value. What the value replaces is the hook's own documented contract; here it's the new label, or the id to select instead. The hook may be async. A throw counts as a reject and is logged as an error. Core runs it with runBeforeCallback(fn, ctx, name), which always returns a promise of { isRejected, hasValue, value }. runBeforeCallbackEager answers synchronously when the hook does and returns a promise only for an async hook, so a click that selects in the same tick stays synchronous for sync hooks. Pick what each hook returns, then rename or select an item. The log shows whether selectedId had changed by the time select() returned. 

el.beforeRenameCallback = (ctx) => {        // ctx: { id, oldLabel, newLabel } + element / controller
  if (ctx.newLabel.length > 20) return false;  // reject
  return ctx.newLabel.trim();                  // replace — or return nothing to continue unchanged
};

// inside the component
const r = await runBeforeCallback(this.config.beforeRenameCallback, this.withContext(ctx), 'beforeRenameCallback');
if (r.isRejected) return;
const label = r.hasValue ? r.value : ctx.newLabel;

const s = runBeforeCallbackEager(this.config.beforeSelectCallback, ctx, 'beforeSelectCallback');
if (s instanceof Promise) s.then(apply);   // async hook: wait
else apply(s);                             // sync hook (or unset): same tick

IA03 · /actions: clickable items and the action event

Every clickable item a consumer configures (action buttons, toolbars, menu items) is an ActionItem: a built-in action name or a custom id, text, tooltip, isDisabled, isDanger, isToggled and more, each dynamic field with a get*Callback(ctx) that wins over the static value. resolveActionItem(item, ctx, defaults) resolves them. Here reset is disabled by the component's own default while the count is 0, and Bold is a toggle (aria-pressed). A click goes through runAction() in one fixed order: beforeActionCallback (false cancels everything) → the item's onClick → the built-in behaviour → the action event and its onAction twin. The event is a notification after the fact: the listener already sees the state the built-in left. A throwing onClick or built-in is logged (console) and the event still fires. While an activation runs, the item is busy (aria-busy on the button) and a second click is ignored. HTML in the light DOM joins in with data-action / data-id, and its other data-* attributes arrive as detail.dataset.

HTML-authored: 

let isBold = false;
el.items = [
  { action: 'add', text: '+1', onClick: (d) => log('onClick', d.count) },
  'reset',                                             // string shorthand for { action: 'reset' }
  { id: 'hello', text: 'Say hello', onClick: () => { … } },
  { id: 'bold', text: 'Bold', getIsToggledCallback: () => isBold, onClick: () => { isBold = !isBold; } },
  { action: 'fail', text: 'Broken built-in', isDanger: true },
];
el.beforeActionCallback = (detail) => detail.action === 'reset' ? confirm('Reset?') : undefined;
el.addEventListener('action', (e) => {
  e.detail.action; e.detail.id; e.detail.source; e.detail.dataset;  // + surface context (count)
  el.count;                                         // already updated by the built-in
});

// inside the component, per click:
await runAction({
  detail: this.withContext({ count, action, id, item, source: 'toolbar', sourceEvent, triggerElement, dataset }),
  beforeActionCallback: this.config.beforeActionCallback,
  runBuiltIn: (d) => this.#runBuiltIn(d),
  emitAction: (d) => this.emit('action', d),
});

IA04 · /menu: context and dropdown menus

openMenu(entries, ctx, opts) renders /actions menu entries against a surface context (here the file that was right-clicked, or { file: null } for the dropdown). at is either a viewport point or an element to drop down from. It handles submenus, both static children and a lazy getChildrenCallback (Move to loads for 700 ms), plain and named dividers (menuDivider('Danger zone'), with leading, trailing and doubled ones trimmed), hidden and disabled items, toggles (Pinned is a menuitemcheckbox that keeps the menu open), positioning through /positioning, and dismissal on an outside press, scroll, window blur, Escape or Tab. The component passes runAction, so a menu item goes through the same runAction() order as IA03 and fires the same action event. A leaf closes the menu first, then runs. Right-click a file, use the Actions button, or focus a file and press Shift+F10 to drive it from the keyboard.

Key (while a menu is open)Does
↓ / ↑Next / previous enabled item, wrapping. Disabled items and dividers are skipped.
Home / EndFirst / last enabled item.
→, Enter, Space on a submenu itemOpen the submenu and focus its first item.
Enter / SpaceRun the focused item. A disabled item does nothing.
← / Esc in a submenuClose that level and focus the item that opened it.
Esc on the rootClose (reason 'escape'); focus returns to returnFocusTo.
Tab / Shift+TabClose (reason 'tab'); the browser then moves focus on.
an item's shortcut (O, F2, Delete)Runs that item, looking in the current level first, then the levels above it.
 
import { menuDivider } from '@keenmate/web-components-core/actions';
import { openMenu } from '@keenmate/web-components-core/menu';

row.addEventListener('contextmenu', (e) => {
  e.preventDefault();
  const ctx = this.withContext({ file });
  openMenu([
    { id: 'open', text: 'Open', shortcut: 'O' },
    { action: 'toggle-pin', text: 'Pinned', getIsToggledCallback: (c) => c.file.isPinned, shouldCloseOnClick: false },
    { text: 'Share', children: [{ id: 'copy-link', text: 'Copy link' }, menuDivider(), { text: 'More', children: […] }] },
    { text: 'Move to', getChildrenCallback: async () => loadFolders() },
    menuDivider('Danger zone'),
    { id: 'archive', text: 'Archive', getIsDisabledCallback: (c) => c.file.isLocked },
    { action: 'delete', text: 'Delete', isDanger: true, shortcut: 'Delete' },
  ], ctx, {
    at: { x: e.clientX, y: e.clientY },        // or an element: the dropdown button
    host: this.shadowRoot,                     // levels + the adopted stylesheet live here
    returnFocusTo: row,
    shouldFocusFirst: false,                   // true when opened from the keyboard
    inheritThemeFrom: this,
    runAction: (item, { triggerElement, sourceEvent }) => runAction({ … }),   // as in IA03
    closeCallback: (reason) => { … },          // 'action' | 'escape' | 'tab' | 'outside-click' | …
  });
});

IA05 · API summary

MemberWhereWhat
static eventsBlissElementThe outward notifications: a bare name or an EventDef (name, property / false, bubbles, composed, cancelable, description, deprecated). Each installs an on<Name> twin. ready is always there.
emit(name, detail?)protected methodAttaches the context, calls the twin with the detail, then dispatches the same object (bubbles, not composed unless the row says otherwise). Returns false when a cancelable event was preventDefault()-ed.
el.on<Name>twin propertyA plain function called with the detail before listeners. Not a listener. A throw is logged and the event still fires.
el.on(name, handler)methodTyped addEventListener; the handler gets the CustomEvent. Returns an unsubscribe function.
controller / createController()getter / protected hookThe public facade, built once, lazily. It's detail.controller on every event and ctx.
eventContext()protected hookEnumerable extras on every detail, read per emit (popup components return their presentation flags).
withContext(target)protected methodAttaches controller + element (non-enumerable) and the extras to a detail or ctx, in place. Fields already present win.
dispatch(target, name, detail, opts), withComponentContext()main indexThe free functions underneath emit() / withContext().
runBeforeCallback(fn, ctx, name?)main indexAsync. false rejects, undefined continues, any other value replaces; a throw rejects and is logged. Unset continues. Resolves to { isRejected, hasValue, value }.
runBeforeCallbackEager(fn, ctx, name?)main indexSame contract. Synchronous result for a sync hook, a Promise only for an async one.
runBeforeCallbackSync(fn, ctx, name?)main indexMust answer now (dragstart, keydown). A returned Promise is warned and treated as continue.
ActionItem / MenuItem / menuDivider(text?)/actionsItem data. Static fields plus get*Callback(ctx) (callback wins), onClick, and for menus children / getChildrenCallback / shouldCloseOnClick.
resolveActionItem, resolveMenuEntries, normalizeActionItems, getMenuChildren, readActionDataset, isActionBusy/actionsResolution helpers: callback > static > component default > base; hidden items dropped; dividers trimmed; string shorthand; data-* minus action / id.
runAction({ detail, beforeActionCallback, runBuiltIn, emitAction })/actionsbeforeActionCallback → onClick → built-in → action event. Busy guard, aria-busy on the trigger. Resolves false when cancelled or busy.
ActionEventDetail/actionsSurface ctx + action, id, item, source, sourceEvent, triggerElement, dataset. One object for beforeActionCallback, onClick, onAction and the event.
openMenu(entries, ctx, opts) → MenuHandle/menu{ isOpen, element, close(), focusFirst(), update() }. No visible item means nothing is rendered and the handle is already closed.
OpenMenuOptions/menuat, host, runAction, closeCallback, renderItem, renderMenu, defaults, prepareItem, placement, offset, cssClass, shouldFocusFirst, returnFocusTo, shouldCloseOnOutsideInteraction, overlayGroup, loadingText, inheritThemeFrom.
--km-menu-* / --_km-menu-*CSSPublic page-wide layer / private per-component layer (set from the component's own variable, no fallback), then --base-* tokens. Full list in component-variables.manifest.json.
Callback or event?
A name ending in Callback is a hook whose return value matters (it vetoes, adjusts or supplies something) and may be async. An event (no suffix, kebab-case, never a composed native name such as click) is a fire-and-forget notification, and its on<Name> twin's return value is ignored.
